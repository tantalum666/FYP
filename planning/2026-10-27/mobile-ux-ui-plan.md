## 1. 最新反馈与取代关系

用户要求手机与网页适度差异化、简洁为主、先规划再开工；随后明确简洁不等于不要虚拟形象。本轮又指出卡片内和底部条里的Alice显得突兀，提出直接全屏，并希望借鉴可能与DeepSeek有关、提供较好情绪价值的“胖头鱼”。

因此，之前的Today／Plan／Assistant／More四标签＋紧凑角色栏退出当前推荐。新建议将Today与Assistant合并为以Alice为主的首页，Plan和More按需展开。**用户提出的是设计方向和疑问；本文的导航、取景、文案及情绪互动细节仍是工程建议，未声称已获逐项确认；实施状态以文首28日记录为准。**

## 2. 手机首页的体验

**打开手机先见Alice，可以直接说话、打字或安静地看她；有需要时查看、记录和确认实际事务。**桌面网页继续适合多日期比较、长文本、批量预览和完整记录。实体常亮屏保持独立构图。三端共享业务数据及权限规则，不共用一套页面排版。

“全屏”指应用可用内容区由角色场景承载，不是把旧小卡片拉大，也不需要强制隐藏系统状态或调用浏览器Fullscreen。Alice不再被装进小矩形卡片，不再在每页底部重复放一个人物条。人物、背景、文字和按钮组成同一画面，保留iOS安全区。

### 首页构图

| 层级 | 内容 | 原则 |
|---|---|---|
| 主场景 | 一个Alice 3D实例、克制背景、自然待机 | 人物原貌完整；取景使脸部和表情可辨；不每切一次面板就重新加载 |
| 顶部轻量控制 | Alice名称／真实状态，Plan／计划，More／更多 | 计划与管理入口一直可发现，不依赖隐藏手势；没有七项底栏，也不再拆Today与Assistant |
| 当前回应 | 一段简短文字；较长内容可展开本次对话 | 不把整段聊天气泡铺满人物，不遮住脸；行动状态与角色表情相互一致 |
| 安排提示 | 最多一条下一项安排或确实需要处理的提示 | 没有内容就收起，不用多个空卡片填空间；完整事项在Plan |
| 底部交互 | 一个输入框、语音按钮、少量附加操作 | 打字不自动开麦；键盘出现时输入区上移，人物改为上方紧凑取景 |

示意先用既有独立角色输出截图呈现无边框舞台。黑底来自当前已保存的真实角色画面，**不是已确定最终背景、美术或灯光**；正式实现应使用已有VRM的实时渲染，校验浅／深环境、轮廓和文字对比后选择。不能把截图拉伸成新模型，也不能用重绘人物代替当前Alice。

### 按需展开的内容

- **Plan／计划：**从顶部或下一项提示进入，同一面板内Calendar／日历与Tasks／事务分段。首次默认日历，返回保留日期、筛选与位置。列表优先，手机不直接压缩电脑宽周网格。日／月选择、重复系列及例外能力仍保留。
- **本次对话：**从More进入完整本次消息及未完成草稿，也可从当前回应展开；不是永久聊天档案。
- **More／更多：**按“对话与记忆、桌面连接、工作空间”分组，容纳记忆、回应偏好、角色外观、通知／Widget、活动记录、外部日历／数据、隐私／语言／时区和账户。主页不展示完整系统提示词。
- **详情与编辑：**短查看用面板；长表单、冲突对照和文件全文审核可以扩展成完整内容页。需要阅读／输入时优先保证可读，关闭后回到同一个Alice场景，不强行在所有管理面板上叠放大人物。

面板必须有明确标题、关闭／返回，焦点进入和返回正确；取消不能丢掉未保存输入。手势可以补充操作，但所有重要操作都有可点按入口。

## 3. 角色与对话如何一起工作

### 一套人物，不同状态

| 状态 | 人物与界面 | 不能混淆的事实 |
|---|---|---|
| 安静待机 | 原版待机／眨眼，少量本地动作；默认不开麦 | 动画不触发后台LLM轮询，不代表已连接AI |
| 文字交流 | 人物保留，当前回应简短，输入框可增长 | 只发送用户提交的内容；键盘不能遮发送／确认 |
| 用户主动语音 | 人物为视觉中心，聆听／回答／暂停／结束状态清楚 | 先获真实权限并建立连接才显示聆听；示意的语音状态不等于实际录音 |
| 草稿或作业 | 显示操作摘要，按Review展开完整内容 | 表情、点头和口型不是批准或执行完成回执 |
| 计划／管理 | 面板从下方展开，场景适当弱化，必要时暂停动画 | 关闭面板回到原场景；不另生成第二个悬浮人物 |
| 离线／出错 | 人物可作为本地显示保留，文字明确连接不可用 | 不用友好的动画掩盖失败，也不把缓存说成最新数据 |

保留Alice原版脸、发、服装、绑定及CC BY-SA 4.0来源；不恢复已否决的A1制作路线。正式实现每页至多一个渲染实例；后台暂停动画并收尾媒体资源。减少动态效果或WebGL失败时保留已许可的静态Alice，不换成字母占位。人物放大后的帧率、内存、能耗和iPhone温度必须实际测，不用“看起来流畅”代替结果。

### “情绪价值”的具体含义

参考[DeepSeek社区作品](../../research/2026-10-27-mobile-companion/deepseek-fish-reference.md)中的稳定性格、短而自然的回复、动作反馈及真实事件接续，形成Alice自己的表达。并未确认用户指的是某一款具体插件；不能把社区作品或人格传闻当成官方产品事实。

1. **先回应，再判断是否需要建议。**用户说累时，给一个贴合当前话语的回应，再让用户选择倾诉或一起处理事情；不立即变成任务督促。
2. **有连续性。**记住的是经用户批准的事实，接续的是实际日历／事务状态；能说清上次还在做什么、这次真正完成什么，不编造共同经历。
3. **有自己的口吻。**默认温和自然，可选择轻松俏皮；轻微幽默不扩成每句撒娇或重复夸奖。严肃／难受话题停止玩笑，用户需要解决问题时能够简洁做事。
4. **回应与动作相配。**用现有注意、聆听、回答及简短回应表现状态，不靠持续大动作制造热闹。
5. **主动互动有节制。**优先使用既有事务跟进与安静时段，不新增常驻模型轮询、密集通知、离开惩罚、好感度催促或养成货币。

示例原创文案：“先缓口气。我听着。想吐槽两句，还是一起看看接下来最轻的一步？”只表示设计方向。本轮示意是确定性脚本，不是模型回答、情绪识别或真人效果评测；固定相机姿态判断不转化为情绪或健康诊断。

这次借鉴不等于选择DeepSeek作为最终底层AI。Qwen Omni仍是已接入／已测基线，其他候选仍开放；先明确对话与表现层，再用相同中文场景比较自然度、记忆一致性、任务准确性与语音表现。旧API预算继续关闭，没有新模型调用。

## 4. 简化界面时必须保留的能力

| 能力 | 手机处理方式 |
|---|---|
| 手动新增／编辑 | 核心标题、开始／结束或下一步先显示；提醒、隐私、时区／日历值可见，更多选项分组；不能静默改变已有字段 |
| 事务跟进 | 截止与下一次跟进分别表达，Waiting保留原因，步骤／进展／暂停／延后在详情；时间经过不能自动算完成 |
| AI更改 | 当前回应给草稿摘要；Review展示修改前后和完整字段，用户Confirm后写入；文件作业继续全文审核 |
| 冲突与未知结果 | 保留草稿和原操作标识，提供版本对照／独立核验；不把重试变成第二次创建，不虚构撤销 |
| 记忆与隐私 | 保存、更正、删除由拥有者决定；配对手机不自动取得拥有者记忆、人格、作业批准或管理权限 |
| 本次聊天 | 沿用登录隔离RAM上下文40条／32,000字符，闲置30分钟及重启清空；不宣称此次改版获得永久或跨设备完整历史 |
| 连接与原生 | 可信HTTPS、Keychain配对、系统共享、主动启用的缓存日历通知、Widget和App Intents继续复用 |
| 缓存与离线 | 显示上次更新时间；主机失联时不确认依赖主机的写入，首版不新增离线写入队列；设备在线与AI可用分别表达 |
| 通知／Widget | 日历通知仍为未来7天最多64项的缓存，远端离线修改不会自动推送；Widget超过20分钟需刷新。事务不冒充已有远程推送 |
| 设备与动作 | 固定机位坐姿仍独立；命名动作请求和实际回执分开，活动输出的停止直接可达；手机界面不代表物理急停 |

手动表单中的可见预填时间由用户保存确认；自然语言请求缺少时长仍须追问。切换到其他管理模式、进入后台或结束语音时收尾麦克风／播放并说明状态，已批准作业独立继续，不把离开页面当作撤销。

首次连接完成后进入Alice主页，不要求先配置AI、通知或相机。手机是桌面工作空间的客户端；蜂窝网络远程可达、真实账户、原生音频和通知交付仍需各自验证。

## 5. UI与验收标准

主要控制保持至少44×44pt、正文／表单约16–17pt；不要靠缩小字解决复杂度。[Apple触控与排版指导](https://developer.apple.com/design/tips/)。角色背景上的文字要有稳定对比；管理面板使用实色阅读表面，不在复杂人物纹理上直接放长表单。

适配320、375、390、430 CSS px、横屏、200%文字和软键盘。默认取景保住脸、输入和当前操作；长回复展开本次对话，不无限覆盖人物或挤掉输入。前后状态不自动改日期、语言或权限；英文默认，简体中文可切换。无障碍名称、焦点、关闭／返回、减少动态效果及VoiceOver另验。

### 实施顺序

| 顺序 | 工作包 | 完成标准 |
|---|---|---|
| M1 | 全屏角色主页与面板导航 | Today／Assistant合并呈现；一个Alice渲染实例；Plan／More持续可达；切面板／返回、窄屏和键盘布局成立 |
| M2 | 日历／事务和编辑 | 列表、详情、创建／更正／完成／恢复走通；保留未保存保护、冲突与未知回执 |
| M3 | 对话表达及语音状态 | 统一输入／语音与草稿；安静待机不启动模型；风格一致、状态与工具结果匹配；媒体生命周期正确 |
| M4 | 管理与原生接续 | 记忆、偏好、记录、数据、配对、缓存通知／Widget入口回归；权限不提升 |
| M5 | 整体验收 | iPhone模拟器构建、真实手机、键盘／后台中断／大字／无障碍／功耗检查；同时回归网页及独立设备布局 |

不通过换布局宣称手机已完成，也不把模型真人表现写成静态示意成绩。手机继续接续现有Capacitor iPhone工程，不重启Senplate或另建数据层。iPhone优先，Android本轮不承诺。
