## 实际交付

- SwiftUI iPhone：登录、Keychain会话恢复、个人／工作身份、语言设置、Overview／Live／Tasks／Records四入口；建议接受、调整、拒绝，任务领取、制作完成、开始补入、关联实测事件、复核／取消及原因。
- React/Vite厨房Web：相同业务链、角色权限、任务筛选、事件来源筛选、经理CSV、最小设备显示页。个人身份为明确空状态，没有虚构餐食或点餐按钮。
- FastAPI／PostgreSQL：首批A01–A19路由、关系数据、会话／资源授权、事务行锁、业务版本、操作幂等、观测去重与乱序保存、单调事件顺序、WebSocket刷新信号及前台重读。
- 独立CLI模拟器：新run、取用／补入、移盘、抖动、相机遮挡、暂停、断线、陈旧、重新绑定及收餐；simulated／replay来源明确。读数与状态没有冒称真实传感器或已训练AI。
- 一台硬件、一个独立称重盘位范围不变；供应商材料、学校建议书、身份资料、V7及VI源文件未被本轮覆盖。

## 工程事实

| 项目 | 当前选择与边界 |
|---|---|
| iPhone | SwiftUI／Observation，最低目标iOS17.0；实际验证Xcode26.6、iOS26.5、iPhone17Pro 402×874和SE3 375×667；未验证iOS17运行时或真实iPhone |
| Web | React19.3、TypeScript、Vite8.3、Lucide；真实字体／控件／图表，非把生成图当UI |
| API | Python3.12、FastAPI、SQLAlchemy、psycopg；15项pytest通过，Ruff通过 |
| 数据库 | 独立PostgreSQL16.14，回环55437，.runtime目录；senplate用于演示，senplate_test专供清理式测试 |
| 服务 | API回环8799；Web回环5177代理/v1；没有外网部署、CORS开放或远程入口 |
| 凭据 | 每个开发用户随机密码、Argon2摘要；.runtime文件0600、目录0700；用户、设备和模拟器凭据分离，客户端没有内嵌密码 |
| 会话 | 8小时；Web HttpOnly＋SameSite Strict Cookie；iPhone Keychain。模拟器签名修正后退出重开可恢复，不用明文偏好保存访问令牌 |
| 图表 | 无效读数形成缺口；iPhone辅助字号改用最近读数列表；状态同时用文字表达 |

| 时间 | 界面香港时区；模拟时钟随输入推进。观察时间、接收时间和实际业务sequence分开；同一演示时间的人工事件按sequence排序 |

原型数据库以模型建立初始表；database.py有一个针对本轮早期调试事件表的追加迁移，保留原行并补sequence。尚未建立面向生产的完整迁移／备份发布体系。

## 已运行的验收证据

主链为1500→1200→700g，建议1000g；接受仅创建一个任务。iPhone进行制作／标记完成／开始补入后仍为700g。CLI增加1000g，Web关联这一新事件，任务完成、当前量保持1700g，没有再加一次计划量。随后iPhone读取1700g及已完成任务。实测补入与计划不同的情况另由API测试验证。
