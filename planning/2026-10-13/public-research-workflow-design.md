# Group 2 · Exact public pages to a cited comparison

Design proposal, 13 October 2026. **Not implemented or live-accepted by this document.** Continues the [capability plan](continuous-agent-capability-plan.md) after the selected-task-watch batch. Baseline reported by the coordinator: published source `e1807f4`; this is a shared workspace with concurrent task-watch work. No application source, shared contract, runtime configuration or external account is changed here.

## Recommendation and smallest useful outcome

Implement **owner-selected public page capture → inspect retained sources → explicitly start a comparison → verified Markdown and CSV**. Example: the owner supplies two documentation pages and the phrases “offline”, “export” and “Linux”; receives a matrix of matching quoted passages and source/time/line references to assess the options. It works without a model key. An available, separately admitted model can already reason over the captured sources through ordinary Work.

Keep capture before run creation in this first slice. This reuses immutable source selection and the existing coordinator without making its selected source scope dynamic, adding a second planner, or granting an AI arbitrary network access. Two explicit actions are intentional: fetching/storing a public page and retaining a Work result have distinct scope. Capture success never silently starts a run, selects a provider, transmits a goal, or shares sources.

A deterministic phrase matrix is useful navigation and evidence extraction, **not a feature-support judgment**. A match may say “does not support offline”; absence of a phrase does not establish absence of a feature. The UI and report must say that. Existing deterministic Work merely compiles excerpts; naming that a comparison without implementing the matrix would not deliver this increment.

Do not ship search, crawling, link following, JavaScript rendering, PDFs, browser automation, authenticated retrieval, credentials, external writes, recurrent recapture, parallel network jobs or paid calls in this slice. This is a real public-document-to-local-artifact workflow, not proof of broad cross-app writes or commercial-agent parity.

## Source-backed seams and changes

The inspected implementation provides:

- `backend/desk/connectors/mcp_transport.py`: public DNS admission, one bounded resolver slot, pinned-address HTTPS with original-host TLS verification, header/body deadline wrapper, 16-KiB headers, identity encoding and byte bounds. `_exchange` is MCP POST/JSON/SSE-specific; do not use it to impersonate a GET or copy its transport into another implementation
- `backend/desk/sources.py`: owner/session-gated UTF-8 snapshots, exact byte hashes, line reads/coverage and bounded retention. `ingest` currently assigns only uploaded-file/artifact origin and does not accept a publication checkpoint
- `backend/desk/file_store.py`: safe immutable reservation, fsync/link/readback, capacity and a trusted checkpoint argument at reservation and final linking. Reuse this mechanism
- `backend/desk/agent_tools.py`, `agent_planner.py`, `agent_runs.py`: source acquisition, deterministic parser coverage, report composition, two real artifacts, immutable per-revision keys and final coverage/readback verification. `artifact_payloads` currently writes an evidence-register CSV, not a comparison CSV
- `backend/desk/agent_run_schemas.py`: fixed source membership, model destination/sharing gates and strict decisions; `ToolObservation` explicitly lacks local-source provenance. Do not relabel a remote observation as an uploaded source or invent line coverage
- `frontend/src/workspace/agent/SourceUpload.tsx`, `RunComposer.tsx`, `SourcePreview.tsx`, `ArtifactList.tsx`, `useAgentRuns.ts`: existing owner-only intake, privacy/response fences, scope refresh, draft guards and actual output access

Proposed modules: `public_http.py` for shared bounded HTTPS primitives; `public_research.py` for capture state and extraction; `research_comparison.py` for the pure typed comparison. Register capture service/routes and an off-default capability in existing runtime/app startup. Keep MCP policy/error behavior through its wrapper; regression tests must prove no endpoint or grant widening. Do not refactor browser routing into this HTTP client: its experimental process/network contract remains different.

## Exact admission; no network before owner action

A local prepare route accepts one exact URL and an optional display label. It validates syntax and returns a review without DNS or HTTP. The owner reviews the entire URL, local retention, and disclosure that the site and DNS infrastructure see the requested host/path and connection metadata. An explicit approve binds review ID, version, canonical intent hash, `public_only: true` and `retain_snapshot: true` to the current real visible owner session. Preparing is not approval; model output cannot call the approval route.

First-version URL grammar deliberately excludes many valid URLs:

- HTTPS only, default 443 with no explicit port; lowercase ASCII DNS hostname, no trailing dot, IP literal, userinfo, query or fragment; reject alternate numeric IP forms and single-label/internal names
- Nonempty absolute path, bounded total URL to 1,024 bytes, ASCII path letters/digits and `/ _ ~ . -` only; reject percent escapes, backslashes, dot segments, whitespace/control characters and empty/ambiguous authority. Show the exact accepted URL; do not silently decode, rewrite or strip parts
- No URL derived from a task, memory, source link, model argument or an autocomplete network service. An owner can paste a URL but must confirm it is public and contains no private/token-bearing path. Reject obvious secret-link shapes defensively; a heuristic cannot certify publicity
- No DNS prefetch, favicon, thumbnail, OG fetch, external link preview or browser redirect caused by displaying a review

Public HTTPS and GET do not prove harmless server semantics. The exact owner action approves this specific retrieval, not arbitrary endpoints on the host. Authentication, sign-in, paywall, CAPTCHA or unexpected permissions stop retrieval. The app never submits credentials or solves a challenge. The URL itself is private workspace metadata even when its target is public; avoid URL logging and query-string APIs.

Use `POST /api/public-research/captures`, `GET /api/public-research/captures`, `GET /api/public-research/captures/{id}`, and versioned `/approve`, `/cancel`, `/reconcile` actions. Existing owner dependency, same-origin/request marker and operation IDs apply. GET detail/list support an explicit metadata-only projection. No frontend-supplied provenance, raw host path, headers, method or extraction code is accepted.

## One shared bounded transport

Extract the existing connector DNS/pinned-TLS/deadline reader primitives into an internal module, mapping generic transport failures back to existing connector errors. Expose a narrow GET operation with code-owned policy values; no public generic HTTP proxy API. Preserve the connector's current POST/SSE contract and its existing limits.

For each approved capture:

1. Check session, expiry, private visibility/revision, capture generation, immutable URL/policy hash, active service claim and capacity before DNS
2. Resolve through the existing system resolver once under the same total budget; reject the entire answer set if any address is non-global. Mixed public/private, benchmark, loopback, link-local, multicast, unspecified and mapped private forms must fail closed
3. Pin one admitted address to the socket. Keep the original hostname for Host, SNI and certificate validation. Do not resolve it again inside connect, inherit proxies, fall back to another resolver or switch to a browser on denial
4. Recheck authority immediately before sending and durably mark the single dispatch. GET only; fixed Accept, identity encoding, fixed product User-Agent, Connection: close. No Cookie, Authorization, Referer, Origin, client certificate, supplied headers, request body, conditional cache headers or goal/query data
5. Accept only status 200. Reject all redirects, including same-origin 301/302/303/307/308; no automatic Location visit. Return a safe reason without turning a sensitive Location into a clickable alternative. 401/403/429 and other failures are terminal for this capture
6. Recheck during bounded reads and before extraction/publication. Close the response/socket on every path; cancellation needs no second request to the remote site

Limits: one capture worker, one shared resolver slot, 20-second monotonic network budget, at most three-second blocking socket phases, 16-KiB headers and 128-KiB body. Check announced size and every chunk; reject missing/invalid/ambiguous length framing where the parser cannot establish a complete bounded response. Reject compressed bodies even if the server ignores identity encoding. No decompression, archives, range stitching, retry-after scheduling or silent prefix capture. A valid chunked response remains bounded; incomplete EOF/framing is not success. Reject multiple conflicting Content-Length/Transfer-Encoding and unsupported protocol upgrades. Test slow header/body drips, not only timeout exceptions.

The existing blocked OS resolver can outlive its caller but has no dispatch authority and holds the one resolver slot until it returns. Socket phase limits are not an OS hard-kill promise. Hide/cancel fences publication even if an OS operation finishes later. Preserve current network restrictions: the known public-DNS failure remains a blocker; this module is not a workaround.

## Safe extraction and immutable provenance

Accept only `text/plain`, `text/markdown` and `text/html` with UTF-8 or no declared charset and successful strict UTF-8 decoding. Reject binaries, PDF, XML/XHTML, JSON APIs, NUL, unsupported charsets and empty results. `text/html` uses a small deterministic standard-library parser, never a browser, shell, eval, CSS evaluator or remote parser service.

The versioned HTML extractor emits text-node content with deterministic block boundaries; ignores comments and script/style/template/noscript/head content; ignores URL-bearing attributes and all subresources; drops explicitly hidden subtrees. Bound nesting to 64 and parser events to 20,000, in addition to input/output byte limits. Malformed/unsupported structures fail closed rather than escaping to another parser. It cannot compute CSS or JavaScript visibility, identify the canonical article, reliably detect paywalls, or prove every emitted word was visually displayed. Label the result “static extracted text” and show it before comparison.

Normalize line endings and whitespace deterministically; retain at most 24 KiB extracted text with logical lines no longer than 1,024 UTF-8 bytes. Reject overflow rather than silently truncate. A documented deterministic wrap can split long text-node blocks; citations then refer to those generated lines, not server source-code lines. The extractor version and wrapping rule must be pinned and golden-tested. No conversion removes inconvenient qualifying text to make a match positive.

Use a trusted `SourceService.ingest_public_capture(...)` path that validates ordinary source constraints, accepts only service-owned acquisition metadata, and passes the capture checkpoint into `ImmutableFiles.put`. It stores ordinary `.txt` sources with `provenance_kind=public_web_snapshot`; the existing upload/from-artifact routes cannot set that origin. Immutable metadata includes capture ID, exact URL, received-at UTC, response status/MIME/charset, raw body SHA-256/byte count, extractor version, extracted byte hash/count, and `coverage=complete_accepted_static_extraction`. Do not retain cookies, server tokens or arbitrary headers. Date/version claims in page text remain untrusted.

Only the extracted snapshot is retained in this smallest slice. Raw response bytes exist in bounded memory during processing and are **not** retained; their digest is an acquisition receipt, not a reopenable raw-page archive. Independently verified source bytes prove the stored extraction, not publication authenticity, factual truth, full-site coverage or original-body recoverability. Never give the extracted hash the label “original HTML hash.” Full-page rendered/visual coverage is explicitly unknown.

Use generated filenames and the existing private store. Retention consumes existing 100-source/64-MiB limits, including uncertain reservations. A maximum 200 capture receipts with one bounded attempt each prevents a separate unbounded journal; cancellation/readback must still work at capacity. The source reservation precedes filesystem effects and a short final transaction fences cancellation/privacy changes. Reconcile may adopt only matching existing final bytes and metadata; it must not publish a leftover temporary file, refetch the URL or manufacture expected output.

No deletion UI or automatic purge is promised. Review must explicitly disclose indefinite local retention and present current capacity. Corrected or refreshed captures create new IDs; equal URLs do not overwrite, imply freshness or extend standing permission. Already-linked files remain retained when a later cancel wins. Hidden mode masks URL, label, extracts, source IDs and hashes; it retains only content-free lifecycle metadata and stop controls.

## Lifecycle and retry

Capture states: `review → queued → fetching → publishing → verified`, plus `rejected`, `expired`, `failed`, `cancelled`, `unknown`. Review expires after five minutes; approved work must start/finish within a 60-second wall-clock ceiling in addition to the network budget. Keep monotonic in-process deadlines and conservative wall-clock restart expiry; clock rollback must not extend authority.

Reserve immutable request hash/operation key before work, use one claim/generation, and persist at most one HTTP dispatch per capture. Duplicate approve and lost-response retries return the original capture/source. A conflicting same-key request fails. Cancel before dispatch prevents the request; after dispatch it stops further reads/publication where possible and cannot erase the request from remote logs. Client close/abort is not server cancellation.

On restart, interrupted pre-dispatch work becomes expired/rejected; dispatched capture without a reconciliable final source becomes unknown/failed with stage evidence, never automatically fetched again. A fresh owner action may create a new capture after displaying that this makes another public request and possibly a new snapshot. This is explicit recapture, not transparent recovery. Completed capture lookup/reconcile remains read-only, including after owner reauthentication; old session authority is never rebound to a worker. Shutdown fences the claim before joining/cancelling worker activity.

Keep network and parsing outside SQLite/control locks. Every late commit and source publication revalidates the same service claim, generation, visible-owner session, privacy epoch and policy. A hide→show transition does not restore old authority. Safe errors contain a code and stage, not reflected HTML, credentials or URL-bearing exception traces.

## An honest deterministic comparison in existing Work

After inspecting captures, the owner chooses 2–4 verified snapshots and 1–6 criteria. Criteria are bounded literal phrases (1–80 characters), not regex, instructions or executable expressions. Add an optional strict `comparison={kind:literal_phrase_matrix_v1, criteria:[...]}` to `RunCreate`, admitted only for deterministic mode, those exact public-web source IDs, no mutations/tool grants/personal context. Goal is retained as context, not interpreted. Source membership and criteria are pinned in the immutable run intent; changing either requires a new run.

Extend the deterministic collect/compose path, not a second job engine:

- Read every selected snapshot through `SourceService.read_all` with current integrity and run coverage checks
- For each criterion/source cell, normalize with a pinned Unicode normalization/casefold rule and find literal substring matches **within each logical extracted line**; no stemming, synonym, inferred units or cross-line semantic matching
- Record total matching lines and the first matching original line, its exact source ID/revision/range/hash, and extraction/acquisition metadata. Bound display quoting to that whole line; additional matches are counted but not quoted. “No literal match in this snapshot” is distinct from unsupported/unavailable/corrupt source
- Produce a Markdown matrix plus criterion sections and a comparison CSV with `criterion, source_id, url, acquired_at, match_state, matching_line_count, quoted_line, start_line, end_line, source_sha256`. Include source register/limitations in Markdown and metadata columns in CSV
- Keep the existing exactly-two-artifact contract; the opt-in template replaces the ordinary evidence-register CSV only for this kind. Ordinary Work output remains unchanged. Use existing safe CSV escaping and generated downloads
- Extend required-outcome verification to require every criterion/source cell exactly once, valid counts, literal quote/range agreement, original selected source coverage, immutable template/criteria hash, and both artifact readbacks. Do not mark success if a failed capture was silently dropped from a declared capture selection; the owner must explicitly choose a different comparison scope

This requires reading full snapshots in the comparison helper: current `read_evidence` puts only an initial excerpt into the report despite recording full local-parser coverage. Do not derive negative phrase matches from that excerpt. Comparison citations can cite the complete locally parsed source ranges, but quoted line references must remain exact. Structured provenance alone does not validate prose, and existing `quality=not_semantically_checked` remains appropriate. Propagate the trusted acquisition origin through `SourceService.view`, source preview, `read_evidence` and artifact manifests; the current evidence shape drops web URL/extractor metadata. Explicitly allowlist those fields in model context only under ordinary source-sharing consent. An uploaded document containing a URL cannot manufacture that origin.

Model comparison is a separate ordinary Work choice over the same snapshots, using existing destination-bound source-sharing consent and selected provider/call budgets. No key or paid budget exists now, so it must remain unavailable in actual acceptance. Do not promise model completion for a 24-KiB source: current 1,800-byte chunks, 32-observation/30-KiB context and attempt caps can yield partial coverage. Do not weaken complete-coverage verification or silently truncate context. No new research network tool is exposed to the model in this slice.

## UI and release ordering

Add a small capture intake alongside local upload in Work, with exact review, source preview, acquisition type/time, safe terminal errors, original-operation recovery, cancel and explicit “Use these sources” selection. Never auto-open fetched links. Memory-only edits, dirty-navigation guard, request identity and owner/privacy/selection response fences follow existing upload/work patterns. English and Chinese must preserve the distinctions between captured, compared, verified bytes and unassessed claims.

Consolidate before declaring this usable: current handoff records an unresolved real-browser React blank mount, CSV local-save uncertainty, and untested latest search/voice interfaces. These are concrete acceptance deficits, not reasons to abandon safe cloud design/tests. Fix/reproduce the blank-mount and output-save path in the authorized existing acceptance route; no production network relaxation or new Mac work is authorized by this design. Do not add a new top-level research dashboard or another unaccepted navigation surface.

**Maintenance should precede broad or recurring capture.** Existing limits count retained terminal work: 100 Sources, 100 Runs and 400 Artifacts; the coordinator additionally reports the in-progress watch batch has a 20-definition lifetime bound. Two fresh sources per comparison alone exhaust an otherwise empty source count after 50 comparisons, sooner with failed reservations or other uploads. No existing source/run deletion UI establishes recoverability. Check capacity at review, approval and publication; a preflight count is not a reservation or guarantee against concurrent uploads. Surface the exact blocked resource and leave existing inspect/download/cancel usable.

A minimal next consolidation slice can expose capacity plus explicit reversible archive/restore of terminal run/watch presentation, retaining IDs, immutable source/artifact links, operation keys and effect receipts. **Presentation archive does not reclaim existing lifetime quotas.** Do not exclude archived rows from counts and call that bounded storage; retained bytes/receipts would grow indefinitely. Real reclamation needs a separately designed recoverable trash/export lifecycle, dependency/reference checks, crash-consistent file moves, restore collisions, a bounded tombstone/receipt policy and explicit permanent-purge authority. Active/unknown effects and temporary-only file reservations are not safe deletion candidates. Removing their rows can re-enable duplicate effects or erase reconciliation evidence; deleting cited sources makes retained reports unverifiable. Source/artifact cleanup cannot be implemented as generic SQL row deletion or directory cleanup.

Therefore prioritize capacity visibility and recoverable lifecycle design immediately after the watch batch, alongside fixing the known mounted-UI/save defects. A bounded experimental capture/comparison implementation can proceed independently with disclosed fixed capacity, but broader repeated-use release should wait for accepted maintenance semantics. If capacity is already exhausted or core Work preview/download is unusable, fix that first rather than expand network formats. This proposal does not itself authorize any deletion or migration.

## Independent acceptance, with stopping conditions

1. **Real local end-to-end fixture:** separate in-process HTTP fixture used only by a test-only connection seam; record actual GETs independently. Owner prepares/reviews two fictional pages, approves, inspects exact retained source bytes, chooses criteria, runs deterministic comparison, then independently reopens/parses Markdown and CSV and recomputes hashes. Assert expected positive, negated-positive text and no-match cells. No model, external account or test-only network flag in production
2. **No-authority negative matrix:** zero requests at prepare, cancelled-before-dispatch, expired review, owner expiry, hide→show, stale hash/version, paired controller, policy change and restart-before-dispatch. Same-key repeat yields one request/source; conflict cannot adopt/cancel an unrelated receipt
3. **Network matrix:** exact transmitted target/headers, no cookie/proxy/referrer/query/goal, private/mixed DNS and rebinding refusal/pinning, certificate mismatch, redirect refusal, compressed/oversized/empty/wrong-type/non-UTF-8 responses, malformed framing, slow headers/body, stuck DNS slot and cancellation during each stage. Existing MCP integration/security suites pass unchanged after primitive extraction
4. **Storage/parser matrix:** hostile script/style/hidden text, nested/malformed HTML, oversized parser events/lines, source instructions/links, injection/formula strings, crash after reservation/write/link, fsync failure, corrupt source and symlink/hardlink/FIFO. Owner-hidden stale workers cannot publish new final bytes. Unknown reservations remain unknown/counted; reconcile sends no HTTP
5. **Comparison semantics:** match after the first 12-KiB excerpt, Unicode criteria, quoted negation, line-boundary split, multiple matches, no match, missing selected source, corrupt snapshot and duplicate/missing matrix cell. Exact quotes/counts are independently derived from golden fixture bytes, not the generator under test. Standard deterministic Work and model protocol behavior remain unchanged
6. **Mounted UI:** actual capture/review/cancel, repeated clicks, lost response/reopen, selection changes, hide/sign-out/offline/stale/late results, navigation with edits, English/Chinese and narrow layout. Inspect final artifacts and actual browser-saved files separately; server hashes alone do not prove browser save. Keep A1/DeviceApp/assets unchanged
7. **Live public acceptance, separately gated:** only in an already authorized environment with admitted public DNS, run the actual production client against two owner-selected exact public pages, record source receipt/observed static text and independently inspect output. Stop on DNS/security/auth/size/redirect failures; do not substitute a developer browser or fake response. Current environment is blocked, so mark this not run
8. **Release evidence:** exact source hashes, focused tests, whole backend/frontend suite, lint/type/build, protected assets, independent reviewer findings and fixes, real UI evidence where available. Parent handles shared docs and any authorized publication. A test count is not the utility measure; the measure is an owner obtaining two inspectable, correctly cited comparison files from their exact selected inputs

Stopping condition for the first implementation is a complete locally verified capture/compare pipeline with all safety negatives, transparent experimental availability and accurate external/UI gates. It does not close the owner's continuous broader capability request or justify live/research-quality claims beyond the evidence.
