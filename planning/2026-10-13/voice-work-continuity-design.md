## Recommendation and completion boundary

Implement **owner-reviewed voice-derived goal → existing Work composer → explicitly retained run → existing review/results/controls**. A single user-input snapshot is enough; do not add voice memory extraction, a second planner, automatic conversation retention, spoken approvals, or an always-connected provider. Keep one product assistant identity while exposing actual voice and work transports separately.

The next software milestone is a durable run with the owner's reviewed goal and bounded provenance, selected evidence, retention acknowledgment, independently verified existing outputs, and working pause/cancel/recovery. A protocol fixture proves this path without keys. It does not prove speech recognition, real microphone capture, speaker attribution, latency, model intelligence or commercial-agent equivalence. Gemini/Qwen remain existing interchangeable adapters and historical candidates, not a new provider selection. No runtime, provider or network calls were made for this design.

## What the inspected implementation actually provides

- [voice.py](../../desk-companion/backend/desk/voice.py): `VoiceService` holds server-side credentials, short-lived one-use connection tickets, a single active connection, session/privacy checks and bounded audio. It persists numeric usage, not audio/transcripts. `session_id` is currently internal. Qwen emits final user input on `conversation.item.input_audio_transcription.completed`; Gemini `inputTranscription` is always currently emitted with `final=False`. Gemini `turnComplete` is an assistant-turn event, **not evidence that a particular user transcript is final**.
- [tool_dispatch.py](../../desk-companion/backend/desk/tool_dispatch.py): `ToolDispatcher` deduplicates provider calls, limits concurrency, cancels late unapproved proposals and reserves capacity for physical-output stop. It has no durable Work creation/approval API. Preserve this boundary.
- [assistant.py](../../desk-companion/backend/desk/assistant.py): tools prepare task/calendar/job effects; confirmation is a separate authenticated action. Voice excludes memory tools. Do not add a provider-callable run start, retention consent, grant, approval or owner-answer tool.
- [AssistantPanel.tsx](../../desk-companion/frontend/src/workspace/AssistantPanel.tsx): currently concatenates user and assistant display strings, drops to the last 3,000 characters and resets both on interruption. It has no stable input-turn identity. The existing owner-only “Work on this…” action copies the typed draft only, through an epoch-fenced `workGoal`; it does not start work. Never parse the combined “You / Companion” display back into an instruction.
- [audio.ts](../../desk-companion/frontend/src/workspace/audio.ts): `interrupt()` clears current playback then sends `interrupt`; `close()` closes the microphone, playback and socket. New audio received later is currently played normally. “Stop speaking” therefore must not be represented as a permanent transport mute or an independently verified remote-model cancellation.
- [RunPanel.tsx](../../desk-companion/frontend/src/workspace/agent/RunPanel.tsx), [RunComposer.tsx](../../desk-companion/frontend/src/workspace/agent/RunComposer.tsx) and [types.ts](../../desk-companion/frontend/src/workspace/agent/types.ts): existing goal handoff, dirty-editor guard, review, fresh-scope gates, operation-ID retry, private epoch and metadata-only stop controls can be reused. `WorkGoalRequest` currently has just ID/text; the composer initially prefers model mode for a supplied goal when available.
- [agent_run_schemas.py](../../desk-companion/backend/desk/agent_run_schemas.py)/[agent_runs.py](../../desk-companion/backend/desk/agent_runs.py): actual owner-session admission; a run needs selected evidence and `retain: true`, not just a goal. Source/context grants and exact text destination are separate. Existing run receipts deduplicate creation. Current model/tool call caps are attempt counts, not money limits.

Relevant unchanged contracts: [durable runs](../../desk-companion/docs/agent-runs.md), [selected personal continuity](../../desk-companion/docs/agent-personal-context.md), [personal context](../../desk-companion/docs/personal-context.md), [provider policy](../../desk-companion/docs/provider-policy.md), and [continuous plan](continuous-agent-capability-plan.md).

## User flow and copy

1. The owner starts voice explicitly using the configured service. The product identity is “Desk Companion”; show voice provider/model and connection state as transport information. Configuration alone is not “connected”. No microphone permission, provider call or paid reconnect is introduced by opening Work.
2. Render bounded, separate input segments and assistant output. Only an input segment has “Use this as a work goal…” / “作为工作目标…”. Nothing is selected by default. A provider suggestion to do work may point to that control but cannot activate it. A nearby speaker, recorded audio or ASR label is not authenticated owner speech.
3. Owner selects one visible input snapshot. Completed-provider input is labelled “Recognized speech; check the wording”. Unfinalized input is labelled “Incomplete transcription; edit and review before use”. Do not auto-combine fragments, silently truncate a goal or interpret “yes” as retention/approval. Where stable turn boundaries cannot be established, allow explicit snapshot review rather than inventing finality.
4. Show editable goal text, the selected snapshot's provenance, and the current transcript-boundary label. Use a deliberate “End voice and review work” button for this initial slice; receiving the draft acknowledgment precedes closing voice. Display “This ends the microphone and speech connection. Existing work continues.” The owner can dismiss and keep talking. Do not close voice on a failed handoff.
5. Open the existing Work composer with only the edited goal and origin reference. Leave evidence, memories, saved conversation, destination sharing and every retention/effect acknowledgment unselected. Keep deterministic mode as the safe voice-handoff default; the owner may explicitly choose an available model. Preserve the current typed-chat behavior unless separately changed.
6. Review names the exact selected sources, actual execution mode, work provider destination if any, call caps and retention. Add “Save this reviewed goal and its work results locally. This does not save the full voice conversation or raw audio.” Model mode separately makes clear that the reviewed goal and admitted selected context go to the chosen work provider, which may differ from the voice provider. Voice consent does not authorize this second destination.
7. “Start work” uses the existing owner-only creation route. Link to the retained run only after a confirmed receipt; an unknown response says “Check whether work started”, retaining the same operation ID. Do not pay for another voice connection or call a model to recover it.
8. Display actual run state and verified outputs through Work. A retained run can outlive the voice socket, subject to existing owner-session/privacy/deadline rules. It is not tied to the speech worker or its cleanup. No automatic TTS or sharing run status/content back into a provider is added.

Unconfigured voice: retain the ordinary typed goal path and say voice is unconfigured. A test harness is not a user-facing fake conversation. Unconfigured text model: deterministic evidence compilation remains available and accurately labelled; do not promise natural-language planning from that mode. A goal without selected evidence stays a draft, not a queued run.

## Minimal provenance contract and code seams

Add a small, provider-neutral transient voice-input ledger, preferably a separate `voice_work.py` module owned by `VoiceService`. The ledger exists to avoid treating arbitrary HTTP/model arguments as a server-observed transcript. It is not a new authorization system or a saved conversation.

### Normalized events and bounded transient state

- A server-issued voice session reference, input-segment ID, revision and sequence identify an observed input snapshot. Include role, text, an adapter-owned `boundary` (`provider_final` or `unfinalized`) and observed provider/model/destination metadata. Backend-generated IDs never come from provider tools. Provider item IDs, if present, are untrusted correlation data only.
- Distinguish append deltas from full replacements explicitly. Qwen final transcription replaces its corresponding input text; repeated delivery is deduplicated. Unknown/malformed role, boundary, oversized content, stale sequence or contradictory replacement cannot make a candidate. Do not infer finality from audio silence, assistant completion or interruption.
- With Gemini's current adapter, preserve unfinalized status unless an actually documented input-final signal is separately implemented and tested. Freeze the owner-selected revision as an `owner_snapshot`; later chunks cannot mutate it. This means the owner is reviewing text, not approving an inferred speech act.
- Proposed engineering ceilings: at most 8 input segments, 4,000 characters per segment and 32 KiB total UTF-8 text per active/just-ended owner session; at most 4 frozen drafts; expire them five minutes after creation, with an absolute five-minute post-disconnect lifetime. Oversize segments become ineligible with an explicit notice, rather than taking the last N characters as a new goal. Expire lazily and at existing watchdog cleanup. No raw PCM, assistant text or tool arguments enter this ledger.
- Bind transient state to the actual owner session hash, voice session and privacy revision. Use the existing privacy/session checks at capture, freeze and run admission. No new bearer credential is issued. An opaque reference is not sufficient without the same valid owner session. No transcript text in logs, usage records, localStorage, URLs or durable receipts before explicit run creation.

### Explicit freeze and durable admission

Proposed owner-only `POST /api/voice/work-drafts` accepts only `{voice_session_ref, input_segment_id, expected_revision}` and uses the real request cookie. It freezes the server-observed snapshot and returns an opaque draft reference, bounded text and server-derived transport metadata. This endpoint has no model invocation, run creation, source selection or durable write. It is not included in any assistant/provider tool schema. A paired-client token, local agent token or owner-shaped object fails admission.

Extend `WorkGoalRequest`/composer state to carry an optional draft reference, revision and displayed provenance through dirty-editor guards. Extend strict `RunCreate` with an optional `voice_origin_ref`; the editable goal remains the existing `goal`. The run service resolves the reference under the same owner/privacy checks while admitting the exact reviewed request. Persist only server-derived origin metadata (channel, observed provider/model/destination, observed time, original boundary, owner-reviewed time, and whether the reviewed goal differs), alongside the already retained final goal. Do not persist a duplicate raw transcript, its unselected neighbors, assistant speech or a raw authentication token. A hash is integrity metadata, not anonymization.

Origin is provenance, never evidence or action authority. The legitimate HTTP review/start is authority for the exact retained run scope; transcription finality, the provider's role label and `edited=false` do not establish who spoke. Do not report speaker verification. Origin metadata must stay out of provider/tool payloads unless deliberately needed and separately admitted; it does not add a source citation, memory fact or approval.

Use existing creation operation-ID dedupe first for an already committed, hash-matching request, under current owner/private read access, so a lost response can recover the same run even after its ephemeral draft expires. For a new run, validate and bind the draft atomically with run creation against concurrent hide/revoke/session expiry. A reference may create at most one run; a second operation ID must recover that same matching creation or fail, never duplicate it. A changed goal/scope with the same operation ID conflicts. Expiry before any creation requires another explicit review or an ordinary typed goal with no asserted voice provenance. Do not silently fall back to a new run without provenance.

Keep the lock order consistent with `AgentContextBridge`/run admission; no ledger/privacy lock across network I/O. Only the receipt plus minimal origin is durable. On restart, unstarted voice drafts are lost; the UI says so. Created runs and their origin survive independently. Deleting/forgetting memory does not erase separately retained run goals/results; apply existing privacy and personal-context fences without claiming forensic or provider-side deletion.

### Speech and work control separation

- “Stop speaking” clears local queued output and requests provider interruption. Add an output-generation suppression latch so late old audio cannot restart playback; release it only on an explicit new user input/turn boundary that the adapter can establish, or keep speech muted until the owner chooses to hear it again. Do not synthesize work pause/cancel from this action.
- “End conversation” stops capture/playback/socket. It retains already-started Work and, for the bounded review grace above, an explicitly chosen candidate. Existing voice in-flight proposal cleanup is preserved; delivered legacy drafts follow their current contract. Work-origin reviews are never enrolled in the voice dispatcher's draft cleanup.
- “Pause work” calls the existing versioned action on a specifically selected run; it fences new steps and conservatively cancels its unconfirmed effects. Resume remains explicit.
- “Cancel work” uses the selected run's existing control and honest outcome/unknown semantics. It does not undo already-confirmed effects or recall provider data.
- “Stop physical outputs” remains its separate immediate safety path. Never rename or route it to speech mute or run cancel.
- Do not introduce spoken run pause/cancel in this slice: run ambiguity and owner identity are unresolved. The visible owner controls remain available while speech is active, and metadata-only stop controls remain available when private detail is hidden.

## Principal and surface matrix

- Valid visible owner on desktop/mobile web: may freeze selected input and explicitly create retained work. Phone hardware does not imply a different authority role.
- Valid owner with private details hidden: cannot read/freeze a voice input or start work; can use existing metadata-only pause/cancel.
- Existing paired controller, iPhone paired token, kiosk/display or local voice-agent principal: retains current voice permissions, but cannot list/freeze owner input, create/read Work or approve run-origin reviews. Show “Open Work with an owner sign-in” without leaking a goal or creating a cross-device inbox.
- Revoked client, expired/sign-out owner, changed session or privacy epoch: clear pending private UI and reject late capture/freeze/start; do not transfer a candidate to a new login.

No re-pairing, capability promotion, new persistent credential, background phone permission, shared URL token, or native permission expansion is required. A future paired-device handoff needs a separately designed owner acceptance channel; do not solve it by weakening `AgentRunService.session()`.

## Tests required before claiming the software slice

Use fake provider/WebSocket events and actual isolated SQLite/files, explicitly marked **protocol-fake**. No microphone, live API, network, hardware or paid budget is required for these tests. Add focused backend tests alongside `test_voice_google.py`, `test_voice_context.py`, `test_tool_dispatch.py` and agent-run tests; add a pure input reducer plus mounted frontend coverage where the available harness supports it.

1. Final Qwen input can be selected; assistant text, assistant audio transcription, provider tool arguments, `turn_complete`, silence and a partial fragment cannot trigger any freeze, run, retention or effect by themselves.
2. Gemini fragmented/unfinalized input can only become an explicit owner-reviewed snapshot; no fake finality. Append/replacement, repeated final events, out-of-order segments and interrupted turns stay separate. Old updates cannot rewrite an open review.
3. A provider-invented `work_start`, approval, memory-write or run-control call is rejected. An owner-shaped dictionary, forged origin fields, guessed reference, wrong session, paired/mobile/agent token, revoked principal and hidden owner all fail the relevant backend routes.
4. Blank/oversize text and UTF-8 limits fail clearly. Fragment overflow never silently creates a tail-only goal. TTL, ledger capacity, client unmount and server restart remove temporary candidates without persisting plaintext.
5. Review starts with no scopes/retention/sharing/mutations selected. Existing dirty Work draft receives a replace-or-keep choice. Closing, Back/Escape, switching conversations, repeated handoff and repeated click do not start work or erase unrelated drafts.
6. Same-operation create retry returns the same run; different payload conflicts; a second operation ID cannot turn one candidate into duplicate work. Lost creation response followed by candidate expiry or restart recovers the committed run only. Uncommitted expiry is a clear failure, never an implicit typed fallback.
7. Hide/show, sign-out/sign-in, owner expiry, endpoint change and privacy revision between capture, freeze, review and admission reject stale use; late async events cannot repopulate cleared UI. Scope changes reset review acknowledgments. Transient fetch failure preserves same-epoch unsent text/IDs but disables dispatch until refresh succeeds.
8. Speech interrupt suppresses late queued/new old-generation audio while leaving the selected run running. End voice closes all capture/playback resources without pausing a run. Pause/cancel touches only the selected run and preserves independent receipt/unknown-effect semantics. Physical stop retains priority under a full tool queue.
9. Deterministic end-to-end fixture: synthetic input → owner review → selected synthetic CSV → retained run → actual Markdown/CSV byte readback → restart/detail lookup. No provider is configured and no “AI understood speech” assertion appears.
10. Scripted model fixture separately covers selected-context/provenance isolation, exact destination review, pending effect review, late result fencing and partial/unmet outcomes. Its success cannot be reported as live model quality.
11. Search SQLite/logs/artifacts after discarded drafts for unique transcript/assistant/tool markers; only the deliberately retained reviewed goal and derived authorized run content may survive. Unselected speech, credentials and raw audio must not appear. This is an application test, not forensic deletion proof.
12. English/Chinese labels, keyboard focus, narrow owner viewport, no accidental paired-control enablement, dirty/retry guard, stop buttons and simultaneous transcript updates need mounted/UI acceptance. Source-string assertions alone do not prove interaction behavior. No new A1/DeviceApp layout redesign is needed.

## Decisions and real-world gates still open

Engineering defaults above are recommendations, not user decisions: owner-only review, one input snapshot, short volatile retention, deterministic default, no auto-retention and no spoken approval. They allow implementation without choosing a model or buying access.

Before real audio/model acceptance, obtain the actual chosen provider/model/destination, suitable credentials through the supported secure route, an explicit total test spending limit, allowed audio/context transmission and a test device/microphone. Do not infer a cash cap from eight model calls. Check current official provider protocol documentation at that time; this design did not perform external research or assert current wire semantics beyond the checked-in adapters.

Future product choices requiring the user's input: whether full voice conversations should ever be retained; whether paired devices need an owner-reviewed cross-device handoff; whether live speech should remain active while reviewing work; and whether a specific selected run's status may be spoken back through a provider. None is required to finish this first bounded slice, and none is silently enabled.

Exit the eventual software milestone only with explicit fake-protocol, local-file, UI and live-condition evidence categories. Continue the wider personal-agent roadmap independently of unavailable keys or audio hardware.
