# Group 2 · One exact public URL to an inspectable source

Implementation design, 13 October 2026. **Initially planning-only; the selected slice is now implemented with frozen aggregate verification passed. No live public request or user-store migration occurred.** Prepared during the coordinator's frozen watch-retention aggregate. Inherits the same ongoing 186-document intake; the coordinator owns shared product/handoff/decision updates and publication. This narrows, without overwriting, [the public research workflow design](public-research-workflow-design.md). Revised after the [independent seam review](../../output/qa/2026-10-13-exact-url-plan-review/review.md); its offline probes are evidence about existing helpers, not an implemented capture service.

## Outcome and boundaries

The smallest useful increment is: the visible owner enters one credential-free public HTTPS URL, reviews that exact destination and permanent local retention, approves one bounded GET, inspects the resulting immutable static-text source, then separately selects it in existing Work. No Work run is created by capture. No search, crawl, link following, subresources, JavaScript, login, browser fallback, redirects, cookies, remote writes, model selection, provider grant or paid call is added. No semantic comparison is implemented or claimed. Existing deterministic Work remains evidence compilation; a future comparison template is a separate increment.

The earlier design says maintenance should precede **broad or recurring** capture and explicitly permits a bounded experimental implementation with fixed capacity. One manually approved capture does not require pretending Source/Work cleanup exists. Current watch trash/purge is not source cleanup. Keep the existing 100-source / 64-MiB source limits, count unknown reservations, and disclose that this version cannot delete captured sources or reclaim their capacity. A full or unreadable capacity ledger is a genuine capture blocker. An unusable source preview/Work output path blocks usable-release acceptance, even when backend fixture tests pass. Neither condition permits lifting quotas, automatically deleting records, rewriting DNS, or routing around denied public access.

Success is one inspectable retained extraction with correct acquisition provenance and original-operation recovery. Full-page visibility, site completeness, factual correctness, model quality and commercial-agent parity remain unverified.

## Inspected seams and actual gaps

- `desk-companion/backend/desk/connectors/mcp_transport.py` already has `public_addresses`, one `_DNS_SLOT`, `_PinnedHTTPSConnection`, `_DeadlineSocket` and `_DeadlineReader`. Its `_exchange` is MCP POST/JSON/SSE and must remain so. The primitives can be extracted once, not copied or used to impersonate a GET. Existing `is_global` admission alone accepts some multicast values on the checked interpreter; capture needs a separate explicit unicast predicate. `McpHttpClient.request` is unsuitable because its failure path may send a best-effort MCP cancellation notification, violating one-request capture.
- `sources.py` has strict UTF-8 source validation, explicit selection and verified line reads. `SourceService.ingest` does not currently take a checkpoint or public provenance. `SourceService.view` spreads existing metadata, so server-created acquisition fields can pass through without rewriting storage.
- `file_store.py` has immutable source reservations, canonical request dedupe, source count/bytes admission, file/directory fsync, no-follow/inode checks and checkpoints at reservation, before temporary write and at final link. Recovery adopts matching final bytes only; it cannot finish a temporary file. Preserve that contract.
- `work_capacity.py` has corruption-aware bounded scalar accounting. Its public `snapshot` is advisory and checks other resource categories too; factor/reuse the source-specific validator for admission rather than treating missing/invalid bytes as zero. `ImmutableFiles.put` currently parses metadata directly for final capacity; the capture checkpoint must additionally enforce corruption-safe accounting inside the same write transaction before insertion.
- `provider_policy.py` protects credential-bearing model endpoints. It is not an arbitrary public-URL admission policy and must remain unchanged. Capturing never updates destination consent.
- `browser_policy.py`/`browser_worker.py` provide fixed Python-docs observations and StackEdit export. Their DNS preflight explicitly does not pin Chromium. They are not the correct fetch transport and are not fallback routes. Their fixed catalog, process policy and known DNS blocker stay unchanged.
- Existing upload, preview, selection, response-fence and dirty-draft patterns are in `frontend/src/workspace/agent`. Add intake there, not a new research dashboard. Backend/source metadata alone does not prove a mounted UI or a saved browser download.

## Proposed internal modules

1. `public_https.py`: transport-only shared primitives extracted from MCP. Own the single resolver semaphore here; re-export compatibility symbols from MCP where tests/internal callers need them. A small `PublicTransportError(code, status)` is translated by MCP to the same existing `CONNECTOR_*` errors and by capture to `CAPTURE_*`. No public generic HTTP endpoint, user-controlled headers or runtime test bypass. Mechanical extraction preserves MCP admission/protocol/error behavior. Capture-only public-unicast validation and the capture-only strict response parser are separately identified changes, never implicit MCP policy changes.
2. `public_capture_policy.py`: strict request/review/result schemas, URL grammar, code-owned limits and versioned pure static extractor.
3. `public_captures.py`: owner-reviewed durable lifecycle, fixed GET client, bounded single worker, API routes and source publication.
4. Small trusted `SourceService.ingest_public_capture` entry point reusing shared validation and `ImmutableFiles.put(..., checkpoint=...)`. No client route can set public provenance. Ordinary upload/artifact behavior remains unchanged.

Avoid a second planner, shared generic job framework, arbitrary network tool or browser refactor. Runtime wiring exposes an off-default experimental `DESK_PUBLIC_CAPTURE_ENABLED=1` application feature only; implementation must not set it in a real environment. This is not a DNS/proxy/TLS/network-security setting. Capabilities can report disabled without making any network call.

## Exact API and owner review

All paths are proposed under `/api/public-research/captures`; real owner session and current same-origin/request-marker checks apply. Strict models forbid extra fields, booleans masquerading as integers, malformed IDs and unsupported literals. Mutations use the existing `X-Operation-Id` (1–100 characters) and `X-Desk-Request: 1`.

The initial URL editor is volatile browser state. Before persisting a review, it explains local review-record retention. `POST /captures` takes:

- `url`: the exact accepted ASCII URL, at most 1,024 UTF-8 bytes
- `label`: optional single-line plain display text, 1–120 characters, no controls; never used as a host path or transmitted
- `retain_capture_record: true`: strict literal acknowledgment that this review, URL and bounded lifecycle receipt are retained even if cancelled

This prepare endpoint does only syntax validation, owner/capacity checks and a durable local review. **No DNS, connect, prefetch, HEAD, GET or external preview.** It returns `capture`, `operation_id` and a code-owned `review`:

- `id` (32 lowercase hex), `version` (positive integer), `state=review`, `intent_hash` (SHA-256), `expires_at`
- Exact `url`, parsed `host`, local label and proposed generated `.txt` display name
- `method=GET`, `public_only=true`, `credentials=none`, `redirects=deny`, `policy_version=1`, `extractor_version=static_text_v1`
- `destination=exact URL`; external disclosure is host/path and connection metadata to the website and DNS infrastructure, never goal, label, private context or credentials
- `retention=local_indefinite_no_delete_control`, raw-body retention `none`, existing source count/byte usage and fixed limits, capture-history usage/limit, advisory timestamp
- Explicit statement: static text may differ from rendered text; content is untrusted; capture does not start Work or grant model sharing

`POST /captures/{id}/approve` takes exactly `expected_version`, `intent_hash`, `public_only:true`, `retain_snapshot:true`. Intent binds capture ID, exact URL, label/generated name, extraction and network policies, retention/disclosure version, original owner session and privacy revision. Approval CAS-checks these values and current capability, visible owner, expiry and capacity; it does not grant host-wide or standing permission. It returns 202/current state. Review approval expires after five minutes using both wall and monotonic clocks; an epoch change, hide→show, sign-out or restart never revives it.

`GET /captures?limit=20&cursor=...&metadata_only=false` and `GET /captures/{id}?metadata_only=false` return bounded current records. Use a stable opaque-ID cursor, maximum 50/page, no search/body query or URL in query parameters. List/detail do not re-fetch and do not imply fresh file verification. Hidden-mode metadata-only output includes only capture handle, lifecycle state/version/timestamps, dispatch-possibility, safe code and cancel availability; omit URL, label, intent digest, source ID, content and hashes. New owner sign-in can read retained records but cannot inherit old worker approval. List/detail/reconcile capture the current request session and privacy/settings epoch, then recheck them immediately before returning private fields, including after file I/O; do not use the old worker epoch as read authority or rely only on React fences/current-visible checks. Hidden projection reads only scalar allowlisted columns and does not deserialize private intent/acquisition JSON.

`POST /captures/{id}/cancel` takes `expected_version`. Require a real owner, but allow the metadata-only stop path while hidden. Revoke generation/claim under the same transaction as publication fencing. Already-linked bytes remain retained; cancellation is not deletion or proof the site received nothing. Hidden stop must still revoke the known capture handle when private intent/acquisition JSON is corrupt: it reads scalar ID/state/version/generation fields, validates the owner and operation collision, and never parses the URL or extraction body. Corrupt identity/control columns fail safely rather than guessing authority.

`POST /captures/{id}/reconcile` takes `expected_version`; require a currently visible real owner. It performs **local readback only**, no DNS/HTTP/retry. Result distinguishes `source_verified`, `source_unknown` and `no_final_source`. It may update local verification metadata, never create/publish missing bytes. A cancelled capture stays cancelled even when a previously linked source is independently verified.

The UI preserves the original operation key through response loss. Reopen/read/reconcile is recovery; a fresh capture is explicitly labelled another request and another possible source reservation. No automatic “retry” generates a new operation ID.

## Durable schema and bounded dedupe

Add one `public_captures` table and one tiny operation-receipt table under **global database schema 3**. This is the selected implementation policy, not permission to migrate a user's store. Fresh fixture stores initialize schema 3. A recognized schema-2 store must refuse upgrade without a separately named explicit offline `allow_public_capture_migration` 2→3 opt-in, with the service stopped and a complete SQLite backup independently verified first. Create both capture tables, their indexes/constraints and `PRAGMA user_version=3` in one transaction; rollback leaves a valid unchanged v2 store. Do not perform migration opportunistically in Runtime/capture-service construction or reuse `allow_watch_retention_migration`.

Schema 3 requires both capture tables with the exact supported column/type/constraint/index structure even when the capability is disabled. Missing/partial/incompatible schema fails closed before journal/bootstrap/runtime writes; never recreate an empty capture ledger with `CREATE TABLE IF NOT EXISTS`, which could erase once-only barriers. Schema 2 with unexpected partial capture tables is not an empty extension and must fail closed. Schema 1 first takes the existing separately authorized 1→2 route, then the separately authorized 2→3 route; no direct or combined migration is implied. Existing v2 binaries reject version 3, but historical binaries cannot be retroactively secured, so the operational prohibition on old binaries touching upgraded stores remains. No runtime database is changed by this planning revision; no generic migration framework is proposed.

`public_captures` fields:

- `id TEXT PRIMARY KEY`, `state TEXT CHECK(...)`, `version INTEGER >=1`
- `intent_json TEXT` (strict canonical record, at most 8 KiB), `intent_hash TEXT` (64 hex), `policy_version INTEGER=1`
- `session_hash TEXT`, `privacy_revision TEXT` (server-generated), `claim TEXT NULL`, `generation INTEGER >=0`
- `created_at`, `updated_at`, `expires_at`, `approved_at NULL`, `deadline_at NULL`
- `dispatch_possible INTEGER CHECK IN(0,1) DEFAULT 0`, `dispatch_at NULL`, `cancel_requested INTEGER CHECK IN(0,1)`
- `source_operation_key TEXT UNIQUE`, `source_id TEXT NULL`, `stage TEXT`, `error_code TEXT NULL`, `acquisition_json TEXT NULL` (strict service metadata, at most 4 KiB)

States: `review`, `queued`, `fetching`, `publishing`, `verified`, `expired`, `failed`, `cancelled`, `unknown`. Keep capture intent/receipt format version 1 and `policy_version=1` distinct from global database schema 3. The source's verification status is separate from lifecycle status. Do not flatten a cancelled-but-retained source into “nothing saved.” A dispatch marker means the request **may** have been sent, not proof the server saw it.

`public_capture_operations`: `operation_key PRIMARY KEY`, `kind`, `request_hash`, `capture_id`, with `UNIQUE(capture_id,kind)`. Persist at most one successful prepare, approve and cancel receipt per capture: at most 600 receipts for 200 lifetime captures. Reconcile is local readback and needs no unbounded durable operation journal. A same-key/same-kind/same-target/hash request returns the original capture's **current** state, not a stale success body. A collision fails before inspecting/mutating any unrelated target. Different-key repeats of an already effected transition are read-only no-ops and do not add a receipt or overwrite the first key. Invalid requests create no rows. Capacity checks happen after original-key lookup so full history cannot block recovery or cancel.

Lifetime review/capture cap: 200, including cancelled/failed/expired/unknown. No automatic receipt expiry, row deletion or ID recycling. Review explains abandoned preparations consume retained history. Avoid an append-only event table: bounded stage/current error plus one acquisition receipt is enough. Do not mistake this cap for sustainable source cleanup.

## One request with exact bounded network policy

Accepted URL grammar deliberately excludes many public pages:

- Literal lowercase `https://`; ASCII DNS host with at least two valid labels, each 1–63 characters, total host at most 253; lowercase letters/digits/hyphens with alphanumeric ends
- Reject IP literals and alternate numeric IP forms, userinfo, explicit ports including 443, trailing dot, single-label/internal/reserved names, empty authority, query, fragment, percent escapes, backslashes, whitespace and controls
- Require a nonempty absolute path with only `[A-Za-z0-9/_~.\-]`; reject `.`/`..` segments and repeated slash ambiguity; reject invalid rather than silently normalize/decode/remove components
- Defensively reject known credential-link patterns; the owner must additionally confirm the URL is public and contains no secret/private token. A heuristic or HTTPS cannot prove either assertion

One capture worker, no waiting network queue: refuse another new approval as busy while occupied; preparing a review remains local. One shared resolver slot across MCP and capture. After approval, enforce a 60-second in-process execution ceiling and conservative wall deadline; 20-second total monotonic DNS/connect/header/body budget, maximum 3-second blocking socket phases. Parser checks checkpoints between bounded events. Stuck OS operations are not claimed to be forcibly killed; an occupied slot cannot spawn replacement workers indefinitely.

Resolve once through existing system DNS with the one shared semaphore. The capture wrapper applies an explicit code-owned `is_public_unicast(address)` to **every** result before choosing one: require a syntactically valid global address and independently reject multicast, unspecified, loopback, link-local, private, reserved and scoped/zone forms. For IPv4-mapped IPv6, apply the same checks to the mapped IPv4 address as well as the outer form; reject on any failed check. Pin tests for benchmark, multicast (`224.0.0.1`, `ff02::1`) and mapped-private forms instead of assuming `is_global` excludes them. Reject the entire mixed answer set, not only the selected first address. Keep the mechanically extracted MCP helper's existing behavior/error mapping unchanged; any future shared hardening needs its own explicitly reviewed tests. Pin one accepted address, preserve original hostname for Host/SNI/certificate verification, and never try another address, resolver, proxy or browser on failure. DNS/connection metadata can be emitted before HTTP dispatch; owner approval covers that exact preparatory traffic.

After DNS/TLS, recheck authority; durably set dispatch-possible under the claim/generation fence immediately before `conn.request`. Then recheck and send exactly one GET, no body. This transaction is the conservative local dispatch boundary; it cannot guarantee no packet occurs after a subsequent cancellation race. A cancellation before the marker prevents dispatch; after it, display that the request may already have been sent. Code-owned headers: Accept for the three allowed text types, Accept-Encoding identity, fixed product User-Agent and Connection close. No Cookie, Authorization, Referer, Origin, client certificate, cache validator, owner label, task goal or user-supplied header. Ignore and never retain Set-Cookie; no cookie jar exists.

Accept only 200. Redirects, 401/403, 429 and other statuses terminate without following Location, authentication, CAPTCHA or Retry-After. Safe errors must not reflect page HTML, Location, URL-bearing tracebacks or tokens. No redirect destination suggestion automatically becomes a new review.

Network caps: 16 KiB aggregate headers and existing slow-header byte/deadline guard; 128 KiB raw body. **For this smaller first slice require exactly one canonical decimal Content-Length, 1–131072; reject every Transfer-Encoding, compression, duplicate length, protocol upgrade, interim-response chain and close-delimited body.** This intentionally narrows the earlier design's optional bounded chunked support, reducing framing/CPU surface; compatibility can be separately reviewed later. Read and retain exactly the declared Content-Length frame; reject EOF before that many bytes rather than saving a prefix. This validates the retained HTTP representation, not socket EOF: surplus bytes or a later pipelined response are neither consumed nor validated, and the connection is closed locally. Reject duplicate/ambiguous Content-Type or Content-Encoding. Use a capture-only `HTTPResponse` subclass/status-line hook (e.g. intercept each `_read_status` return) that rejects every 1xx before `HTTPResponse.begin()` can consume a 100 Continue. Set this response class only on capture connections; MCP keeps its existing response class and SSE/chunked behavior. Inspect raw field multiplicity with `headers.get_all`, not flattened `getheader` strings. The capture-specific header admission rejects parser defects, obsolete folded/continued fields, malformed field names/colon syntax, and ambiguous or non-CRLF framing; raw-line validation must happen before the standard header parser discards or normalizes evidence. Use byte-level fixtures that preserve malformed bytes and 100+200 sequences, not only server frameworks that canonicalize headers.

The shared `_DeadlineReader` header-phase guard includes buffered body read-ahead, so near 16 KiB it may conservatively reject a syntactically smaller header. Disclose and preserve that conservative cap; do not relax it to make boundary tests pass. Capture can separately validate syntactic raw header bounds, but this does not remove the shared read-ahead guard. Certificate errors/security denials remain failures.

Close socket/response on all paths. Cleanup is local only: do not reuse `McpHttpClient.request` or send MCP cancellation notifications, another GET, a retry, or a remote cleanup request. Reads and extraction take place outside SQLite/control locks; only brief admission/dispatch/publication CAS transactions hold locks. Do not call a method that takes another SQLite connection from inside a capture checkpoint; checkpoints receive the existing connection.

## Extraction and provenance

Accept only `text/plain`, `text/markdown`, `text/html`, with absent or UTF-8 charset and strict UTF-8 body decoding. Reject NUL, binary/XML/JSON/PDF, conflicting MIME/charset and unsupported control characters. Retain plain `.txt` output; Markdown source markup is data, not rendered output.

`static_text_v1`:

- For plain/Markdown, normalize CRLF/CR to LF and reject unsupported control characters. Preserve text/qualifiers; no summary, title detection or semantic filtering
- For HTML use standard-library `HTMLParser` with explicit bounded stack and fixed HTML void-element handling. Exclude comments and `head/script/style/template/noscript` subtrees; exclude `hidden` and `aria-hidden=true` subtrees. Ignore all attributes other than code-owned visibility checks and every URL/subresource
- Unknown tags can contribute text; malformed nesting outside the explicitly documented handling, depth over 64 or more than 20,000 parser events fails closed. Parser decisions require golden fixtures, including void elements and truncated tags. Feed bounded chunks and check authority/deadline between chunks and bounded parser events; do not run one unchecked full-document parse. No CSS evaluation, JavaScript, external entities/parser service, shell or eval
- Emit deterministic LF block boundaries; HTML text whitespace normalization is versioned. Strictly bound output to 24 KiB and logical lines to 1,024 UTF-8 bytes. Wrap at the last whitespace fitting the byte limit or at a Unicode codepoint boundary, never split a codepoint. Count the LF within the 1,024-byte line budget. Normalize every supported Unicode line separator consistently with `SourceService.splitlines(keepends=True)` into LF before wrapping/counting, and golden-test U+0085/U+2028/U+2029; unsupported control separators fail instead of producing disagreeing citation lines. Reject total overflow/empty result instead of truncating
- Source citations name generated extraction lines, not original HTML lines. CSS-hidden/generated/paywalled content cannot be universally detected. Reject recognized auth/challenge responses; do not claim arbitrary 200 login/paywall detection is solved

Raw response bytes live only in bounded worker memory and are not retained. Compute raw SHA-256/byte count, then extracted SHA-256/count. Service-owned metadata added to the immutable source:

`provenance_kind=public_web_snapshot`, `capture_id`, exact `url`, `received_at` UTC, `http_status=200`, admitted `response_mime`, `response_charset=utf-8`, `raw_sha256`, `raw_byte_count`, `extractor_version`, `extracted_sha256`, `extracted_byte_count`, `coverage=complete_accepted_static_extraction`, `raw_retained=false`, `rendered_coverage=unknown`.

The display filename is generated, e.g. `capture-<id>.txt`; a label is separate optional metadata. No arbitrary response headers, cookies, remote file names, server timestamps or script output are trusted provenance. Acquisition digest is not a reopenable raw-page archive or authenticity/fact check. Source metadata keeps `untrusted=true` and `provider_sharing=not_granted_by_selection`.

Expose a minimal internal transaction-aware source admission helper and exact `(kind, operation_key)` reservation lookup; private `_files`, `_row` and `_read_bytes` methods are not treated as public capture APIs. The lookup validates SQL ID/kind/key identity, canonical stored request hash and bounded immutable metadata (capture ID, exact URL/policy/extractor, acquisition and extracted hashes/counts). It never opens a nested connection under an existing transaction, and never searches by URL/hash alone. Reuse the existing file writer/readback through minimal safe adapters rather than duplicating it.

Use server-derived immutable `source_operation_key=capture:<id>:source:v1`. Before calling `put`, record bounded acquisition metadata and enter publishing under the capture fence. The current `put` checkpoint runs before reservation insertion and does not receive the new file ID; do not claim it can atomically attach that ID. Save the returned source ID after `put`; after a crash, reconcile resolves exactly one private-file row by kind/key and validates immutable metadata/hash/capture identity before adoption. Never search by matching URL or text hash alone. A same URL/bytes in a fresh expressly approved capture is a new provenance event, never an overwrite or implicit consent reuse.

Recheck known source count/bytes at prepare, approve, before DNS and under source reservation; final exact byte admission remains authoritative. The checkpoint distinguishes a fresh reservation from an existing exact source operation: add the prospective bytes/count only before insertion, not again at final linking. Inside the reservation transaction, first identify/validate the exact existing operation; only a new operation needs complete source-accounting admission and prospective count/byte charging. At final linking the row is already charged. Original-key recovery must not fail merely because its already-counted reservation filled the last slot, history is full or an unrelated accounting bucket is corrupt; validate this row's identity/hash/metadata/integrity and retain the existing no-rewrite behavior. Reconciliation invokes exact lookup and independent local readback only, never `ingest`, extraction regeneration or new-admission checks. Bypassing new admission does not permit adoption of a corrupt reservation. A racing ordinary upload may consume the last slot after network work; return a clear capacity failure with no fabricated source. Do not promise preflight reserves capacity. Unknown accounting blocks only new intake; retained inspection/reconcile/stop remain available. No source/run/artifact quota change.

## Crash, cancellation and authority matrix

- Lost prepare response: repeat same key/content retrieves original review, zero DNS
- Duplicate approve/concurrent clicks: one state transition, one active claim and at most one possible GET
- Crash/restart before dispatch: expire/fail the old attempt and clear authority; never auto-resume old approval
- Durable dispatch marker then crash before send: unknown whether GET happened, no replay; conservative marker is intentional
- HTTP received but no reserved/final file: fail/unknown with stage evidence; no HTTP retry and no regenerated extraction on reopen
- Reservation/temporary file only: source remains unknown and counted; reconcile cannot rename/link/rewrite it
- Final link before pending unlink: both names normally have `st_nlink=2`; current readback rejects `FILE_READBACK_MISMATCH`. Keep unknown, counted evidence for separately authorized manual maintenance. No automatic unlink, repair or promotion, even if both contents look correct
- Pending unlinked but before directory fsync/readback or capture/source association: the matching single-link final file can be recovered by exact operation lookup plus existing independent file/directory fsync and byte readback. Never adopt a different capture's row
- Cancellation/privacy epoch change before final link: checkpoint prevents publication. A hide→show transition never restores generation/session authority
- Cancellation immediately after link: preserve file and lifecycle cancellation independently from source status, even if ingest throws before returning its ID due to privacy/session loss. Do not mark the source absent or verified automatically. Current visible owner may later resolve the exact private-file key and inspect/reconcile; cancellation remains cancellation and nlink=2 still remains unknown
- Session expiry/revocation while blocked: checkpoint prevents subsequent authorized activity/publication; already-sent traffic cannot be recalled. Reauthentication enables reading, not continuation under old authority
- Shutdown: mark service stopping/revoke claim before bounded join; no second worker while blocked thread still owns the slot. Restart never treats thread absence as proof no request occurred
- Damaged/missing ledger, intent hash, source mapping or receipt: unknown/fail closed. No opportunistic adoption, refetch, temporary repair or hidden cleanup

Content, including instructions, URLs, “approved” text and suggested tools, is untrusted data only. Capture introduces no model tool route. Later Work membership is an explicit owner selection; provider/model data-sharing and call budgets remain the existing separate gates. Never accept remote observations as approval or derive new capture requests automatically from source text.

## UI and test deliverable

A small “Capture one public page” intake beside SourceUpload owns volatile URL/label, explicit review-retention checkbox, retained review, approval, stop and original-operation recovery. Do not auto-select the new source in a Work draft; successful capture offers its existing plain-text preview and an explicit later selection. Extend the preview metadata to show static acquisition origin, exact URL/time and extraction/raw-retention limitations; current filename/ID/hash/line display alone does not establish that provenance. Render plain text with the existing `<pre>` path. Dirty-navigation and duplicate-submit locks, owner/privacy/revision response fences, safe English/Chinese errors and hidden-mode metadata controls must follow existing patterns. No URL preview, auto-link navigation, favicon fetch, remote image or raw HTML rendering.

Required offline evidence before any application release:

1. Pure schema/URL tests: credentials, ports, encoded/numeric hosts, private hostnames, query/fragment, ambiguous paths, controls, same-key conflicts and strict-literal acknowledgments; prepare makes zero DNS/socket calls
2. Actual local HTTP fixture through a test-only injected connection seam; independently record method/target/headers/count. Production DNS seam never admits localhost/test flags. Assert extraction/source bytes and hashes independently, then explicitly select source in ordinary deterministic Work and reopen its existing artifacts
3. Network failures: capture-only multicast/public-unicast and IPv4-mapped admission, mixed/non-global DNS and rebinding pin, shared busy resolver, original-host SNI/certificate validation, no proxy/env/cookie/redirect inheritance, exact caps including conservative header/body read-ahead, byte-level 100+200 and other 1xx fixtures, header continuation/defect rejection, malformed/duplicate framing, all disallowed encodings/types, incomplete body, slow header/body drip, cancellation at each phase and response/socket close
4. Lifecycle races: same and different-key duplicates, unrelated-key conflict, lost responses, owner/paired denial, expiry, hide→show, policy change, shutdown, blocked resolver and restart at every dispatch/publication boundary. Count actual fixture GETs separately from dispatch-possible markers
5. Storage: fresh schema 3, recognized v2 without/with separate opt-in, v1 staged-only migration, partial/missing/wrong-constraint capture tables even while disabled, transaction rollback/restart and historical-binary refusal; 99/100 source limits, near 64-MiB limit, corrupt/unknown accounting, 200-history cap, concurrent uploads, source reservation crashes, fsync failures, temporary-only/nlink=2 unknown versus single-link final recovery, symlink/hardlink/FIFO/inode change, cancelled-after-link and mismatched capture/source receipt. Full capacity or unrelated corrupted accounting must not block valid original lookup/cancel/readback; corrupt exact reservations still fail closed. Hidden cancel must tolerate corrupt private intent JSON, and list/detail/reconcile must recheck response privacy after I/O
6. Parser golden tests: whitespace/newlines including Unicode line separators and multi-byte wrapping, negatives/qualifiers retained, hidden nested/void/malformed tags, scripts/styles/templates, attributes containing URLs, injected instructions, control characters, event/depth/output caps, Markdown and non-English text
7. Existing MCP/provider/browser/source/artifact/Work suites unchanged, including exact MCP error taxonomy and behavior after shared primitive extraction. Whole backend/frontend, lint/type/build and protected A1/DeviceApp/assets follow coordinator's frozen-batch checks
8. Mounted UI acceptance separately: review/cancel, response-loss reopen, explicit selection, preview, stale/hidden/identity/offline fences, draft navigation, narrow layout and both languages. Independently inspect actual browser-saved outputs before claiming save acceptance

No live public URL is contacted to write this plan. Public-DNS acceptance remains separately gated and must use the actual production client in an already authorized environment. Stop on denied DNS/security/auth/redirect/format/size and report the exact blocker; no fallback infrastructure or settings change. No live model/budget is available or assumed.
