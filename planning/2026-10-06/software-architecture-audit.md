## 1. 架构判断

**目前不需要推翻重写或微服务化。** React／TypeScript → FastAPI业务服务 → SQLite／本地工作进程适合三人原型。真正缺的是执行作业边界、异常与取消的正确语义，以及可独立检查的结果；增加模型数量不能解决这些问题。

| 层级 | 职责与本轮结论 |
|---|---|
| 界面／语音入口 | 共用身份、事务与工具入口；常亮布局独立。增加作业审阅／结果／恢复，语音接收不等待慢工具 |
| HTTP／WebSocket与授权 | 拥有者会话、配对和本机工作进程身份分离；模型与配对终端不获得作业批准接口 |
| 确定性业务层 | 日历、事务、草稿及新JobService各自维护状态与版本；作业成功不自动代表事务完成 |
| 持久化 | SQLite事务和操作ID复用，新增作业／事件历史；不把内存中的语音连接当持久记忆 |
| 执行器 | ComputerExecutor负责受限动作，VerificationReceipt独立校验结果。当前只有应用专用目录笔记适配器 |
| 后台与设备 | 有界作业工作循环和安全健康状态；固定摄像头、姿态复测与硬件停止仍独立；仍要求单API worker |

`app.py`继续负责装配，`jobs.py`、`computer.py`、`tool_dispatch.py`分开业务、设备能力与会话调度。较大的TaskPanel／Dialogs可以在后续功能变更时逐步拆分，不在本轮为了“层级”制造大量无行为收益的重写。多进程／分布式租约、通用GUI隔离及可强制终止外部进程仍不是当前实现。

## 2. 本轮实际补齐

专用笔记闭环：准备Unicode文本 → 拥有者核对全文及目的地 → 意图哈希／版本批准 → SQLite排队 → 后台新建文件 → 独立读回核对 → 持久状态／历史 → 再次核验。只使用生成文件名，不提供任意路径、shell、URL、覆盖、删除或自由应用控制。

- 5分钟待批准、60秒执行期限；相同操作键去重，不同内容拒绝
- 事务版本在批准及调度前重新校验，关闭事务后旧意图不能执行
- 未开始的取消没有文件副作用；开始后的取消与已提交结果分别记录
- 重启时未完成写入转unknown，旧运行令牌失效，不盲目重放；只读核验恢复结果
- 语音工具独立排队；普通2并发／8未完成，32调用及一个Stop保留槽，64结果队列；取消含迟到草稿与发送中的结果
- 新增Computer jobs中英文界面，完整文本及目标审阅、实时状态、取消、未知结果核验和请求恢复
- 保持后台AI默认关闭、每天20次尝试及原语音600秒／45秒限制，没有新增持续收费模型轮询

这是运行主机上的真实文件操作，不是跨设备PC控制。Pi部署后仍只写Pi的应用目录。使用说明见[computer-jobs.md](../../desk-companion/docs/computer-jobs.md)。

## 3. 审查发现并修复的具体问题

| 问题 | 根因 | 修复与回归 |
|---|---|---|
| 文件已写成但核验抛错后显示failed | execute和verify共享“执行前拒绝”异常分支 | 分离写入／核验阶段，写后核验异常保留unknown；恢复适配器后只读对账成功，不改文件时间 |
| 长语音会话无法调用Stop | 32调用总限额在Stop保留槽前执行 | 专用第33槽，只有已发送且异步任务真正结束的Stop记录可回收；普通配额耗尽仍能停止 |
| 结果队列背压泄漏任务 | 已算出结果不代表结果已入队／发送 | 不回收仍阻塞的生产者，关闭时保留清理引用；满64队列测试覆盖 |
| 打断后旧草稿或旧response.create仍发送 | 发送前只取一次结果快照，帧间可被取消穿插 | 立即取消标记、发送批锁、逐帧复查、独立于可回收缓存的代次栅栏；客户端与提供商阻塞窗口均有回归 |
| 老事务的相关作业消失 | 先取全局200条再按task_id筛选 | SQL先筛选，未解决作业优先；201条无关新记录不会遮住旧任务 |
| 恢复请求清空新草稿／批准挂起阻碍取消 | 全局pending写入与本地表单、busy混用 | 只清理同标题／全文／task_id的恢复内容；取消独立于普通写入busy；异步读取使用代次防旧结果覆盖 |
| 松散结果可能冒充成功 | 仅判断verified字段不足以证明授权意图一致 | 严格布尔值与完整回执校验，文件名／字节数／哈希／执行器／范围逐项匹配；7类伪回执测试 |
