## 1. 先明确要交付什么

本项目要做的是**有桌面实体终端、能在用户授权范围内操作电脑或软件的个人 AI Agent**。自然语音、持续记忆、事务跟进和日历构成统一体验，但只有“能持续聊天／提醒”不足以满足这次明确的产品定位。

一条完整旅程应是：用户从设备说出任务 → 助理理解并必要时澄清 → 屏幕展示目标、范围和待确认动作 → 获得相应授权 → 电脑侧实际执行 → 独立读回结果 → 把完成、失败、等待或结果未知写回同一任务 → 用户稍后从设备、手机或电脑继续。没有实际回执时不能只凭模型说“完成”就记作成功。

### 已明确的用户要求

- 三人项目；用户主要负责软件／AI，另外两人主要负责硬件。本轮没有把两个硬件工作包擅自对应到具体姓名，也没有重写学校文件中的贡献比例。
- 个人 Agent 的核心包括真实、受限的电脑／软件操作，不能以陪聊或持续在线体验代替。
- 设备、语音、日历与任务使用同一助理身份和持续状态；不为每个入口另做一个互不认识的机器人。
- 现有日历与三端软件是基础，应复用，不推翻重做。
- 实体方案围绕 LUWU RIG-Arm、Raspberry Pi、屏幕及可拆卸迷你桌面清洁模块继续评估。
- 将 amontlabs/lcu 纳入 computer-use 候选，并优先核验其是否适合本组。

### 必须保留的已有要求

固定摄像头 → 个人标定 → 可见性／持续时间判断 → 具体反馈 → 再观察并记录结果，仍是必做的坐姿闭环。个人 Agent 定位是本次增加并强化的核心，不是无声取消此前已明确的坐姿要求。姿态摄像头保持固定，不随机械臂转动。

### 尚未确定的事项

最终语音提供商、文字推理模型、LCU 正式采用、目标电脑系统范围、清洁模块控制器与机械接口、完整 BOM、采购、自动回座、无线充电均未确认。ESP32 只是清洁模块控制器候选。概念图表达外形和模块关系，图中尺寸是粗略概念，不能直接当加工图、承重依据或工程要求。

## 3. 统一助理，不等于永不断开的模型连接

### 建议的首版架构

1. **一个实时语音模型**负责自然听说、打断、简短推理和工具请求。它是用户面对的声音入口，不是持久数据库或权限裁判。
2. **确定性的本地任务核心**负责身份、偏好、任务／进展、计划检查、授权、幂等键、版本、截止时间、执行状态和证据。网页与语音都通过它。
3. **可选文字推理工作进程**处理较长规划、多步电脑任务或到时需要语义判断的检查。按实际需要调用；不是强制要求每次语音再串联第二个模型。
4. **可替换执行器**承接经过校验的动作：优先明确业务 API／本地工具，其次浏览器自动化，再按场景使用 GUI computer use。
5. **独立本地硬件控制**负责经过验证的机械预设、限位、超时和停机。云模型不能直接输出无限制电机角度，断网不能使停止失效。

设备的声音、屏幕、任务与结果都引用同一个拥有者、task_id 和事实状态。用户认为是在与同一助理继续交流，不需要了解后台用了几个模型。个性、授权偏好和必要记忆持久化；不能把保留全部原始音频／转写作为维持人格的前提。记忆需有来源、时间、可检查与纠正／删除入口；这是新设计要求，不是当前任意长期记忆已完成的声明。

### 对当前代码的准确理解

- 语音模型的工具请求已经直接交给 `assistant.tool` 受限业务层，不是每次先经过文字模型。
- 一秒任务检查主要读取 SQLite 中的到期条件并执行规则逻辑，不是一秒调用一次 LLM。
- 30 秒的可选文字增强循环只是检查入口。实际调用还要求后台 AI 已启用、提供商已配置、存在有效待处理提示，并受每日最多 20 次尝试的限制；失败也计入限制。不能把循环频率写成持续收费模型轮询。
- 当前语音总时长默认 600 秒、空闲上限默认 45 秒，并未实现 provider session resumption。持久任务在数据库里，不等于语音 WebSocket 永久在线或对话上下文无限保存。
- 当前接收路径会等待工具处理完成。把长时间电脑工作直接塞进去可能阻塞后续接收；应先改成提交任务后快速返回 `job_id`，由工作进程执行并推送状态。提供商宣称支持异步工具，并不会自动把本项目变成异步架构。

上述现状可回查固定基线源码：[调度循环](https://github.com/tantalum666/FYP/blob/5b8ce5b81dd075cae3cef6787c964bf0406591e2/desk-companion/backend/desk/app.py#L50-L71)、[规则入口](https://github.com/tantalum666/FYP/blob/5b8ce5b81dd075cae3cef6787c964bf0406591e2/desk-companion/backend/desk/runtime.py#L85-L88)、[文字增强门槛](https://github.com/tantalum666/FYP/blob/5b8ce5b81dd075cae3cef6787c964bf0406591e2/desk-companion/backend/desk/text_ai.py#L288-L345)、[语音工具等待及会话限制](https://github.com/tantalum666/FYP/blob/5b8ce5b81dd075cae3cef6787c964bf0406591e2/desk-companion/backend/desk/voice.py#L486-L565)。

### 拟议执行状态与恢复契约

建议任务执行使用：待澄清 → 待授权 → 排队 → 执行中 → 等待用户／等待外部 → 验证中 → 已完成／失败／已取消／结果未知。它与用户管理的事务状态关联，但不能简单混成一个字段。

每项外部写入绑定：拥有者、明确目标、授权范围、动作参数摘要、对象版本、operation_id、执行器、时限和取消代次。审批只覆盖当时的意图与版本；目标或内容实质变化时重新审阅。模型只能提出动作，不能获得通用“确认自己”工具。

- 读取可以受控重试；写入先判断是否具有可靠幂等能力。
- 若“保存成功但回执丢失”，先用操作 ID 或独立读回确定状态；不要盲目重复点击。
- 已提交到第三方的动作不能因用户打断语音就谎报“已撤销”。分别显示“取消未开始步骤”“请求停止执行”“已提交，正在确认结果”。
- 程序重启、连接中断或执行器崩溃后，恢复任务记录和证据；对结果未知的外部写入先对账，不能自动重放。
- 超时、失败和取消必须有可核对的日志；向模型的错误结果保留原有错误含义，不改写成成功。

## 4. Computer use：把 LCU 放进候选，先证明再采用

### LCU 的适用边界

[amontlabs/lcu](https://github.com/amontlabs/lcu) 是开放源码的接入／适配层，复用本机已安装的官方 ChatGPT 桌面应用内的 CUA runtime。它不是重新开源了整个 Codex 电脑操作引擎，也不意味着把原厂 runtime 打包进 FYP 就获得再分发许可。LCU 自身 MIT 与原厂应用／runtime 的条款应分开核验。[来源与许可边界](https://github.com/amontlabs/lcu/blob/bad4fdd7744539ed04ad1a2ce9b930eb62324b22/docs/PROVENANCE.md)

本次资料快照：2026-10-06，LCU main `bad4fdd7744539ed04ad1a2ce9b930eb62324b22`；已发布 v0.9.5 的提交为 `641295e851182f7f2088b68cf4f8022b4700744c`，标签日期 2026-10-05。main 与 release 不是同一版本；实现验证必须重新固定具体版本及已安装官方应用版本。

- 当前公开目标：Apple Silicon macOS；Ubuntu 24.04 兼容的 Linux ARM64／x86-64，需实际 X11 桌面与 D-Bus。Windows 是暂缓候选，不作为首版可交付承诺。
- 文档中的 **Pi adapter 是 Pi coding-agent 框架**，不等于 Raspberry Pi 硬件已经通过验证。Linux ARM64 支持也不等于本组 Raspberry Pi OS、图形栈和整机负载自动兼容。
- macOS 有原厂按应用授权，长期授权管理会要求本人 Touch ID／密码等交互；这些权限不是 FYP 文档推送顺带取得的。
- Linux 原厂 runtime 没有同等按应用授权；Pi 框架本身也没有通用权限系统。因此“装了 LCU”不构成 FYP 的权限隔离，必须在执行前由服务与 OS／隔离环境强制约束范围，不能只给模型一段禁止访问的提示词。
- 上游有特定 harness、固定 fixture、部分真实模型与独立保存读回证据，但不能推出 Gemini／Qwen 与 FYP 已端到端打通，也不能把某次 MCP fixture 当全部 GUI 安全性测试。[适配与授权](https://github.com/amontlabs/lcu/blob/bad4fdd7744539ed04ad1a2ce9b930eb62324b22/docs/ADAPTERS.md)／[验证矩阵](https://github.com/amontlabs/lcu/blob/bad4fdd7744539ed04ad1a2ce9b930eb62324b22/docs/PARITY-STATUS.md)

用户指出 LCU 比此前提到的低星候选更值得关注，因此将其提高到优先调查位置。Star 只能帮助发现社区采用度，不能代替许可、生命周期、权限与可靠性证据；本稿不把会变化的计数当选型门槛。

### 建议拓扑

Pi 上的麦克风／触屏 → 本地会话与任务核心 → 获授权电脑上的配对执行服务 → API／浏览器／GUI 适配器 → 原软件 → 独立状态读回 → 同一任务记录／屏幕／语音。

PC 服务必须校验身份、目标应用／浏览器 origin、允许目录、操作类别、版本与时限。拟议PC执行层若把截图、OCR、文件片段或工具结果送往云模型，需明确提供商／目的地、必要数据范围与用途，并取得相应授权；本机配对或应用控制权限不自动等于云端传输许可。应裁剪／遮蔽无关私人内容、避免发送凭据，并明确服务端与本地的保留／删除策略。设备配对不自动授予整个电脑或所有账户访问。尽量使用临时测试资料、独立浏览器 profile、隔离账户／VM 和最小权限；任意浏览器页面、邮件或文档里的文字都不能扩大用户授权。未建立强制边界前，只做隔离 fixture 的概念验证。

LCU 适配需要保留原始初始化指令、工具描述、工具结果和 isError；使用真实 session／turn 身份；处理真实授权交互，并在结束／中断时调用对应清理。不能由模型伪造批准，也不能靠随便创建新 session 绕过拒绝。具体 API 与可见工具以固定版本官方源码为准。

### 对照与退路

| 路线 | 适合什么 | 主要限制／本轮结论 |
|---|---|---|
| 明确软件 API／现有内部工具 | 日历、任务、确定字段的读写与结果查询 | 优先复用已有可验证契约；外部服务仍需相应权限 |
| [Playwright](https://github.com/microsoft/playwright) | 自有测试网页和结构化浏览器流程 | Apache-2.0 浏览器自动化工具，不是完整桌面 Agent 或权限系统 |
| [PyAutoGUI](https://github.com/asweigart/pyautogui) | 简单跨应用输入／截图原型 | BSD-3-Clause 许可；坐标／焦点／窗口变化敏感，不自带语义规划、授权或独立成功证明 |
| LCU | 复用原厂 CUA 的桌面／受支持浏览器接入 | 优先做 Mac 小验证；第三方适配与专有 runtime 依赖必须保留为风险 |
| [OpenAI CUA sample app](https://github.com/openai/openai-cua-sample-app) | 学习代理循环、浏览器／桌面执行与电脑环境契约 | MIT 示例，不是生产安全沙箱承诺，也不等于模型 API 免费或直接支持所有第三方模型 |

Computer-use 核心需求不依赖某一个开源包装器。如果 LCU 的运行时许可、稳定性或授权约束不适合，换执行器；不能悄悄把电脑操作删成“以后可加”，再把持续聊天称为完成 Agent。

### 第一轮证明矩阵（计划，尚未执行）

| 场景 | 可观察验收证据 |
|---|---|
| 读取指定测试应用内容 | 目标窗口／来源明确，独立读取与返回内容一致 |
| 输入指定 Unicode 文本并保存到测试文件 | 独立文件读取比对精确内容；仅截图不够 |
| 在自有测试网页完成一次低风险表单 | 独立页面／存储状态核验，记录操作 ID |
| 未授权应用、目录或 origin | 服务／OS 拒绝，目标数据无变化；不是模型口头说不会 |
| 用户取消仍待确认的动作 | 无输入／保存发生，状态明确取消 |
| 写入已提交后再取消 | 保留真实提交结果，不假称回滚；后续步骤停止 |
| 超时、断线、进程崩溃、丢失回执 | 显示结果未知并读回；重启不重复保存／点击 |
| 重复请求、旧版本、旧授权 | 去重或冲突，旧意图不得误执行 |
| Stop／Interrupt 与新一轮恢复 | 对应会话停止、清理生效，新任务不会继承旧动作 |
| 页面／文档含“忽略限制”等内容 | 只作任务数据，不能获得新权限或传出无关资料 |

先通过固定脚本／fixture，再接一个真实候选模型，最后接语音入口。逐层报告已经测试的操作，不把“能连上 MCP”写成“个人 Agent 已完成”。

## 5. 自然语音选型：能力证据与本组体验分开

核对日期为2026-10-06。建议保持 Gemini／Qwen 为本组现有适配基础的首轮对照，复杂工作是否需要独立文字模型由实测决定，不是本轮替用户锁定供应商。

- Google 在2026-09-15将 `gemini-3.8-live` 和 `gemini-3.8-live-extended-thinking` 列为 GA；前者面向低时延对话，官方说明默认异步 function calling，后者强调较强后台推理。2026-09-22 的 Flash TTS／Flash-Lite TTS 是另一类文本转语音发布，不能把 TTS 新版直接称为 Live 语音 Agent 新版。[发布记录](https://ai.google.dev/gemini-api/docs/changelog)
- 使用 Live 的工具、会话恢复与长会话能力仍需按最新[能力说明](https://ai.google.dev/gemini-api/docs/live-api/capabilities)和[最佳实践](https://ai.google.dev/gemini-api/docs/live-api/best-practices)实现。模型端异步不免除本地 job_id、幂等、恢复与验证责任。
- Qwen 的 `qwen-audio-3.1-realtime-plus` 是当前自然实时语音候选，官方资料明确列普通话／粤语支持；具体模型、账号区域、endpoint、计费和工具行为需在开通／测试前重新核对。它的商业 API 不等于同名开放权重可以直接部署到 DGX／V100。官方当前还说明联网搜索与 Function Calling 不能同时启用；做工具任务时必须相应配置。[实时语音指南](https://www.alibabacloud.com/help/en/model-studio/qwen-audio-realtime-user-guides)／[型号与区域](https://www.alibabacloud.com/help/en/model-studio/qwen-audio-3-1-realtime-plus)

## 6. 实体终端与清洁模块

用户指定的外形参考为 [LUWU RIG-Arm MakerWorld 页面](https://makerworld.com/zh/models/2913469-rig-arm-desktop-embodied-ai-arm-llm-multimodal?appSharePlatform=copy#profileId-3258768)。它作为机械／具身交互候选，不自动把原厂 AI、摄像头布局或控制协议带入本组产品。已有[专项 PR #1](https://github.com/tantalum666/FYP/pull/1)继续提供组件、接口与停机证据缺口。

建议硬件职责分层：

- Raspberry Pi：触屏、日历／任务核心、本地语音入口、固定姿态观察与设备状态汇总；具体 Pi 型号和整机性能需测。
- RIG-Arm：在验证过的负载、速度、工作包络与限位内执行少量命名预设。现有 PCA9685 实现不能直接当作 RIG 总线舵机适配。
- 可拆卸迷你桌面清洁模块：独立控制与可断开模块，ESP32 可评估；先明确吸／刷／移动方式、回执、供电、安装与拆卸安全。
- 固定姿态摄像头：不随臂动作；如果 RIG 自带可动摄像头，不能直接替换已标定的固定视角。
- 实体安全：手动停机、掉线超时、动作限幅与电机供电边界必须独立于云语音／模型；未校准时默认不运动。

清洁模块要优先验证桌边坠落、线缆缠绕、夹点／吸口接触、拆卸时电气状态、碰撞、噪声与姿态摄像头遮挡。先做受控区域和人工在场台架，不把自动导航、回座或无线充电列成已经承诺的首版功能。机械效果、清洁效果、Agent 任务成功和姿态改善分别测量。

## 7. 三人分工与实施顺序

当前只确认责任方向：用户负责软件／AI，两位组员负责硬件。建议的硬件 A／B 是待组内认领的工作包，不声称某人已经完成。既有 40／30／30 是学校计划比例，不是本轮实际工作归属。

| 阶段 | 主要责任 | 可交付物与完成条件 |
|---|---|---|
| P0：冻结最小 Agent 场景与权限契约 | 用户主导，三人对齐 | 选少量电脑／软件真实任务，定义输入、许可、回执、失败和停止；保持坐姿与日历必做 |
| P1：Mac 电脑执行器小验证 | 用户软件／AI | 在独立测试范围比较 LCU／API／浏览器路线；跑第4节证明矩阵，记录实际 OS、runtime、版本与独立读回证据 |
| P2：持久执行与确认层 | 用户软件／AI | job_id、状态机、授权意图／版本、幂等／未知结果、断线恢复、日志；重启不重复外部写入 |
| P3：一个声音入口串起真任务 | 用户软件／AI；硬件协助音频 | 语音调用同一任务工具；长任务不堵听说；粤语／混语／AEC／成本对照后再选提供商 |
| H1：RIG 与显示台架 | 硬件 A 待认领 | 机械安装／电源／线缆／屏幕、协议与状态读回、工作包络、停机；与固定相机不冲突 |
| H2：可拆卸清洁模块台架 | 硬件 B 待认领 | 机构、控制器、供电／连接、桌边防护、独立停止与噪声证据；不提前承诺回座 |
| P4：整机联调与验收 | 三人共同 | Pi 触控与语音、电脑任务、日历、姿态复测及硬件安全并行；故障恢复与费用记录完整 |
| P5：学校证据整理 | 三人审阅 | 报告逐人实际贡献、实测与模拟分开、引用来源、演示可复现；学校正文另行按批准范围修订 |

下一步建议先做 P0／P1，避免把大量时间花在持续聊天或外壳后才发现电脑执行路径不可用。硬件同学可并行完成 H1／H2 的纸面接口与安全计划，未经台架批准不移动设备。

仓库学校材料列有10月26日 Progress I，以及2027年4月19日／26日前后的最终交付节点；这是既有文件中的计划，不是本轮重新核实的学校最新期限。排程前以当前课程通知确认，不据此声称导师已批准新个人 Agent 定位。
