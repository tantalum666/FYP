## 1 最终软件要完成的四条流程

1. **安排一天：**在手机、电脑或触摸屏录入事项 → 同一后台保存 → 概览、日／周／月视图一致 → 到时提示 → 确认、延后或完成。
2. **坐姿反馈：**固定摄像头获取有效头肩关键点 → 个人标定 → 持续偏离判断 → 具体屏幕／声音／灯光提示 → 复测 → 记录已调整、仍偏离或无法判断。
3. **自然交谈与办事：**本地唤醒 → 自然说话与打断 → 查询真实日程或提出改动 → 必要时澄清／确认 → 本地工具执行 → 根据真实结果回答。
4. **设备联动：**日历和姿态事件改变角色状态及获准的硬件输出；硬件失联或未验证时明确不可用，不能把界面动画当机械动作成功。

日历、姿态和语音各有独立能力及测试；任一语音提供商不可用，不应拖停本地日历与姿态。角色与日历可先同屏，另一个显示输出以后接入，不预先决定最终屏幕数量。

## 2 工程起点与技术选择

新代码放在独立的 `desk-companion/` 目录；原 `apps/`、`services/`、`tests/`、数据库和Senplate品牌保留。开发名称暂用 **Desk Companion**，只是描述用途，不算正式品牌命名。

| 层 | 本轮采用的工程起点 | 理由与边界 |
|---|---|---|
| 界面 | React、TypeScript、Vite | 共用界面逻辑，分别做电脑、手机尺寸和触摸屏布局；不把响应式浏览器测试称为原生App验收。 |
| 手机安装包 | 后续以Capacitor接iPhone | 复用界面，另做权限、配对、签名及真机网络；不在第一批冒称已经装进手机。 |
| 设备界面 | 同一构建产物，Pi Chromium kiosk | 现场大按钮、可读时间和提示；实际触摸与开机运行在Pi阶段验证。 |
| 本地核心 | Python、FastAPI、SQLite | 单台原型无需数据库服务器；一个业务服务负责写入，事务、版本与迁移从首批建立。 |
| 时间／重复 | IANA时区、Python zoneinfo、dateutil recurrence | 保存当地时间与时区，限定查询范围展开重复，处理单次例外；不按固定24小时毫秒数推算所有日期。 |
| 界面更新 | HTTP操作＋版本化状态通知／轮询恢复 | 业务状态落库，断线重连读最新快照；通知不是唯一记录。 |
| 姿态 | 独立采集／推理进程＋本组持续判断模块 | 只传结构化状态到业务层，队列有界；设备性能与真实准确率单独验证。 |
| 语音 | 可替换提供商适配器＋受限工具层 | 不把模型名称写进日历业务；先把工具及确认正确性做稳，再接自然语音。 |

本机已核Node 22.22.3、npm 10.9.8及uv可用。新工程独立锁定依赖，旧工程环境不升级。开发先监听回环地址，真实局域网配对在后续批次完成后开放；公网部署不属于本轮。

## 3 界面与内容安排

手机与电脑管理界面采用克制的浅色中性底、深色正文、少量蓝紫强调色，精细分隔线和清晰时间轴；无食物项目Logo或绿色品牌继承。英文默认，简体中文可切换并保存。界面控件和文字由代码实现，ImageGen只提供设计参考。

| 入口 | 主要内容 | 主要动作 |
|---|---|---|
| Today | 时间、日期、今日安排、下一事项、待处理提醒；天气和姿态按实际接入状态显示 | 快速添加、打开事项、完成／延后、查看当天安排 |
| Calendar | 日／周／月切换、时间块、全天事项、忙闲与冲突 | 日期导航、新建、批量日期、重复、编辑单次／整组、删除 |
| Records | 日程变更及提醒记录；随后加入姿态事件／复测结果 | 按类型筛选、查看发生时间，不生成无依据的健康或效率分数；日期筛选留后续 |
| Device / Settings | 语言、时区、连接、隐私、提醒设置；后续配对、标定与硬件能力 | 修改真实可用设置，说明尚未接入的设备状态 |
| Assistant面板 | 后续语音状态、关键转写、拟议动作、确认及结果 | 查询、澄清、确认、取消、打断；不在无模型时伪造AI聊天 |

电脑以侧栏和宽日历为主；手机以底部导航、日列表和全屏编辑为主；设备首页已依用户9月30日意见另做[常亮界面](../2026-09-30/device-display-spec.md)：大时间、月历、近期安排，暖灰日间／深色夜间，操作收进触摸面板，不常驻App栏。共用组件不等于把所有屏幕布局缩放一次。

## 4 数据规则：先定清楚再写界面

### 日程和重复

- 单次事项、批量日期、周期规则分开。批量选择生成独立事项并保留批次ID；周期事项保存规则及例外，不无限复制记录。
- 事项有稳定ID、标题、地点、备注、起止、时区、全天标记、日历分类、隐私、忙闲、提醒、来源及版本。新增、更新与删除保存操作记录。
- 全天事项用日期范围，结束日不包含在内；普通事项使用明确当地时间和IANA时区，返回可比较的UTC时刻。
- 重复先支持每日／每周／每月／每年、间隔及可选结束日。首批按公历；农历生日重复另行实现，不与双历显示混淆。
- 每月31日或2月29日等不存在的重复日期跳过，界面说明该规则；不静默改成月底。夏令时不存在的时刻拒绝或跳过，重复时刻明确选择规则并测试。
- 单次修改／删除保存例外；修改整组须明确选择。第一批不加入复杂“本次及以后”系列拆分。
- 查询限有界日期窗口，过宽请求明确拒绝；不能只返回部分数据却显示为完整月历。

### 保存、冲突与同步

- 服务端是同一份日程的权威来源；每次操作有唯一ID，重试沿用原ID，不重复创建。
- 修改带所见版本。另一界面已改过时保留本地草稿并提示重新核对，不静默最后写入覆盖。
- 冲突基于占用时间的实际发生项计算，全天、跨日与重复例外进入相同规则；提醒用户，不擅自改期。
- 本组内部多端同步与外部日历同步分开。预留provider／external ID／sync version，但没接外部服务时不会显示“同步成功”。
- 保存中、已保存、离线、结果未确认、版本冲突分别呈现。后台不可达时不允许产生看似成功的改动。

### 隐私、提醒与AI

- 初期一个拥有者、本地认证；以后用短期配对和可撤销终端访问。私人字段不能只靠前端隐藏。
- 第一批私人／可展示标记用于本组已授权界面及隐私展示；实际对外分享在后续单独完成，不能把标记当作分享链接。
- 日程提醒由后台按真实时间生成并持久化；确认、延后与完成分别记录。刷新、重连或两页同时打开不重复生成提醒。
- 第一批验收屏内提醒与状态。手机系统后台推送、可靠响铃和设备语音输出另做；保存一条待提醒记录不等于声音已经播放。
- AI写日历使用“提议→澄清／确认→校验→保存→真实回执”；工具不能任意SQL、shell或舵机角度控制。
- 取消语音时取消尚未执行的请求；已经提交的写入查询实际结果，不能假装回滚。

## 7 本次要运行的检查

后端以隔离测试数据库验证真实业务，不清空演示或旧Senplate数据：

- 创建、批量、重复提交、操作ID冲突和事务回滚。

- 重复及跨日冲突；私人投影不泄露内容；未认证请求受限。
- 到时提醒、提前提醒、确认／延后、事件更改后的旧提醒失效，以及重启恢复不重复。

前端做类型／构建及浏览器实际操作：创建→看到→编辑→另页刷新→完成／删除，失败时保留草稿。检查英文／简中、键盘焦点、弹层返回、长标题、空状态、窄屏、触屏尺寸。ImageGen参考与实际截图逐项比较布局、字体、配色、留白、控件与文案，记录必要的动态内容差异。

API通过不代表界面通过；浏览器手机尺寸通过不代表iPhone安装与Pi触摸通过。相机、模型、语音和机械动作没有实际执行时均保持未连接／未验证。
