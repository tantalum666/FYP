# Group 2：日常语音查询的5秒响应目标

日期：2026-10-15；补充至2026-10-17。状态：**工程验收方案与离线工具测量完成；所选Omni已真实合成短测，浏览器实际播音／Pi端到端统计与逐轮10秒处理仍未完成。**

本稿补充[当前语音比较](../../research/2026-10-15-voice-ai/voice-model-comparison.md)。用户明确：询问“我下一周有什么会议”时，10秒已经偏久，约5秒最自然。型号选择必须加入实际响应速度；综合能力、原生双工或厂商首包数字不能代替这一要求。用户后来选择Qwen3.8 Omni并批准本轮合成资料短测最多5元；这不是日常运行预算。

**10月16–17日实际补充：**[Omni QA](../../output/qa/2026-10-16-qwen-omni-integration/verification.md)的两次成功虚构日历回复均读出三项会议，合成最后有效样本至基于工具结果的语音首包收取为3.176秒／2.619秒。一次较早改口／打断失败也保留。没有标注首个有用词的实际播放时刻、真实麦克风或Pi；两次成功不能统计p50／p95，不能称本节5秒验收已通过。适配器已补正确周一至周一的右端排除指导、函数关联与取消回归；逐轮10秒控制仍待实现。

## 1 用户要求与工程验收口径

- **用户要求：**日常查询需在10秒以内回答，以约5秒为自然体验目标。
- **工程建议：**本地日历只读查询，从用户最后有效语音结束到设备播放首段有真实查询信息的语音，目标p50不超过3秒、p95不超过5秒；10秒仍无有效结果，按超时处理。分位数是本组提出的验收办法，不冒称用户已经指定统计口径或现成性能保证。
- “好的，我查一下”、音效、A1动作或泛泛解释只计首音，不能算作5秒的有效答案。空日程也必须来自实际查询。
- 冷启动新会话与已就绪会话分别统计；连接、丢失语音、请求失败、回答错误或超时不得从成功率分母里删去。首次系统麦克风授权单独记录。
- 计时起点是最后有效语音样本的结束，而非VAD确认结束的较晚时刻；终点是客户端实际播放，不是服务器收到音频块。测试夹具／经许可的标注确定起点，使用同一单调时钟或经校准的关联时间。

| 指标 | 用途 |
|---|---|
| 首音延迟 | 记录是否及时接话；允许包含铺垫，不用于证明有效答案达标 |
| 首段有依据的答案延迟 | 本项目5秒目标；必须包含正确周范围、实际数量／一项会议，或有依据的空结果 |
| 完整列表可用时间 | 另行记录；语音先说摘要，完整列表可以另行展示，不强迫几秒内念完所有会议 |
| 长任务完成时间 | 报告生成／应用操作等另测，不把“已接收作业”当任务完成 |

[OpenAI语音评价指南](https://developers.openai.com/cookbook/examples/audio/voice_agent_evaluation)的通用response latency允许合格铺垫语音计入；本组保留该指标，同时增加更严格的有依据信息指标，不能将两者混报。

## 2 日历查询的处理路径

用户语音流 → 当前语音模型识别意图 → 一次calendar_query → 本地SQLite和重复规则展开 → 紧凑结果 → 流式播报短摘要。

已保存日历的只读查询不需要先启动研究Agent、网页搜索、通用电脑作业或额外高推理模型。使用Live时，同样应让简单查询进入轻量的后台服务／工具路径；不能只因增加了委派层就断言必慢，也不能默认每次先调用最强后台模型。

实现／试测时应满足：

1. 在已由用户启用的短语音会话内复用连接；用户主动开始后可并行准备必要资源。不因A1常驻而提前开启麦克风、上传私人日历或维持整天收费连接。
2. 发言期间就发送小音频块。当前采集为40ms块、收到输出即排入播放，保留这种流式路径；记录实际端点检测、网络和排队时间。
3. 日常查询使用型号正式支持的低延迟配置，复杂推理按需升级。不将某家的推理参数名套给其他型号。
4. 正确确定“下周”的工作空间时区和边界，回复时给出日期范围。默认下一完整周一00:00至再下一周一00:00，右端不包含；不能误用“未来7天”或今天范围。
5. 同一轮只查询所需范围，短摘要先出；缩减无关上下文、冗长工具输出和额外模型往返。编辑／删除仍取得新版本、明确确认并读回。
6. 连接、模型生成、工具排队、查询、结果回传与客户端播放分别计时。模型的孤立首音成绩不是完整工具回合延迟。
7. 每轮需要10秒的无有效结果处理和迟到结果控制；超时提示不能编造“没有会议”或“已完成”。当前600秒会话／45秒空闲限制不等于已有逐轮10秒超时。

播报示例，仅假设查询确实返回3场会议：“下周10月19日至25日有3场会议，第一场是周一上午10点的项目讨论。”先给有用信息，详细展开按需继续；这不是用户真实日历。

## 3 5秒的工程时间分配

下表是排查预算，不是实测，也不以各阶段分位数相加证明端到端SLO。

| 阶段 | 建议预算 |
|---|---:|
| 确认发言结束／端点检测 | 0.8秒 |
| 模型生成查询工具调用 | 1.2秒 |
| 本地工具排队、查询和结果序列化 | 0.2秒 |
| 基于结果生成首段有效语音 | 1.8秒 |
| 其余网络与播放缓冲 | 0.5秒 |
| 余量 | 0.5秒 |
| 合计 | 5.0秒 |

优化提示词、模型、思考配置、连接复用或流式输出后，仍须测正确率。不能通过截掉未说完的话、忽略改口、播放无依据的缓存答案来降低时间。

## 4 已检查的当前实现与离线证据

- [calendar_query](../../desk-companion/backend/desk/assistant.py)直接调用Store.snapshot，返回限定字段和隐私投影；这一调用不需要LLM或外部日历HTTP刷新。
- [ToolDispatcher](../../desk-companion/backend/desk/tool_dispatch.py)将工具放入线程并与语音接收分开。普通工具最多两个并发；占用／数据库写锁时的排队尚未包含在本轮测量中。
- [语音代理](../../desk-companion/backend/desk/voice.py)收到工具结果后直接回传；Gemini当前端点配置为700ms静默。12秒连接与15秒就绪是失败上限，不是固定等待，也不是5秒验收。
- [前端音频](../../desk-companion/frontend/src/workspace/audio.ts)流式播放，最小排程余量20ms，超过8秒排队会关闭；尚无首段有用语音的测量／逐轮10秒处理。新连接ready之前音频会丢弃，所以冷启动的提示和完整收音须另验。
- 本地文字规则主要处理今天／明天；不得把它当作已经支持“下周”的语义快答路径。当前语音路径让模型提交明确的日期范围。

隔离Mac、Python3.14.5；全部为合成数据，使用真实ToolDispatcher、AssistantService和SQLite，含日／周重复，查询2026-10-19至26日。每种规模100次、返回33项，结果序列化为7,188字节。

| 合成日程总数 | p50 | p95 | 最大值 |
|---|---:|---:|---:|
| 100 | 1.949ms | 2.391ms | 3.931ms |
| 500（当前应用上限） | 5.213ms | 6.002ms | 6.254ms |

私密标题隐藏另行核对通过。夹具写入不计入耗时；首个测量不是操作系统冷启动。没有真实日历、模型、网络、麦克风、TTS、浏览器播音或Pi。**此结果仅说明该样本中的本地工具不是秒级等待来源，不能证明端到端5秒已经达标。**脚本及原始结果见[QA](../../output/qa/2026-10-15-voice-latency/verification.md)。

## 5 数据新鲜度与复杂任务

响应快和日历数据新是两项要求。读取当前本地版本；未来若加缓存，须按日历版本、时区／范围、权限和隐私设置失效。外部日历尚未同步时，应说明来源与时点，不把已有导入记录称为完整最新云日历。不能为省时提前把未请求的私人内容送给提供商。

报告生成、资料研究或较长软件操作仍使用持久作业、进度和取消。初次接收反馈的目标可以同样短，但它是“已接收”，不能计为任务完成。复杂后台工作不应占住日常只读查询路径。

## 6 下一步与选型影响

10月15日Gemini3.8普通Live、Qwen Audio3.1 Plus、Grok3.0及Realtime2.1为工程候选；后续用户已选Omni，当前优先验证该确切配置，其他比较保留历史。无型号已经通过本组实际播音5秒统计验收。

每个确切配置用相同普通话、英语、粤语及混说场景，分别测新会话、已就绪、重复／例外、隐私、修改后立刻查询、空结果、改口、工具占用、网络慢／断连与超时迟到。至少记录p50／p95、10秒内成功率、日期范围／会议内容正确率、工具次数、实际usage及账单，不只报平均首音。
