## 数据与默认值（工程选择）

- 菜单归属当前监测run／餐期；每次新的隔离演示可以播种三项演示菜。价格为HKD演示数据，非餐厅正式报价。历史订单保存名称、价格、份量及菜单版本快照。
- Workspace有不含权限的公开菜单代码；二维码仅编码`senplate://menu/<code>`。App只解析本协议与严格代码，不打开未知网址、不从二维码授予工作权限。
- 一个已绑定菜品使用measured库存，其他项目用人工维护的份数。普通自助菜只浏览；staff_portioned模式下才能按标准克数点单。一个run不能混用同一盘的自由自取和按单配餐。
- 标准演示份量100g；数量1–20，最多10种不同项目；金额用整数分。菜单管理version、顾客quote_version和传感snapshot_version分开。管理version包括人工库存修改；quote_version只随价格／名称／描述／发布／供应开关变化，连续测量或正常出餐不会让未改变报价的购物车过期。
- 经理可修改名称、价格、描述、过敏原资料、发布／供应开关及人工库存；本批监测菜标准份量固定100g。旧订单不追溯改价；提交时旧quote_version返回409并保留购物车供复核。可售情况在提交和接单时都重新校验，提交不预留。

## 核心状态

submitted → accepted → preparing → ready → collected；submitted可直接由本人取消，或厨房拒绝。accepted阶段可申请取消，厨房批准后释放预留；有待处理取消申请时不能开始配餐。preparing及ready不提供顾客自动撤销。履约后的取餐不再减供应，也不表示已经付款。

所有写入采用原操作ID／幂等键、expected_version及后台权限校验。接单和整单预留在同一事务；不能部分偷偷接受或让两个订单重复占同一份。个人操作查询只读本人，工作操作按场地及角色；经理不能靠个人接口读取他人订单，厨房访问使用工作接口。

## 物理量、预留与配出

S为最新有效物理净重，R为已接受尚未核对的克数，B首批为0。可再承诺量=max(0,S−R−B)，未知／陈旧时为null；在制补餐量不加入当前S。

开始配餐记录会话、绑定修订、当前序号和预计克数；单盘位一次只允许一个称重配出窗口，且与等待核对的补入互斥。重量已经下降时先更新S，R仍保留；确认新的、有效的、尚未关联的减重事件后才释放相应R，不再改S。人工库存项在确认配出时原子减实际份数、释放预留；不等不存在的称重事件。

严格测量流程要求匹配预计克数；偏差只可由经理明确说明原因后确认，保留计划／实际及差异，不改原测量。没有对应有效事件时保持待处理，不伪造自动核对成功。已有未完成订单／预留时不得重新绑定、换供餐方式或开始另一个run而隐藏责任。

演示验收：S=2000、两单预留300＋500、可再承诺1200；配出第一单300后S=1700、核对前R=800、可再承诺900；确认后R=500、可再承诺1200；取餐后仍为1200。

## API族

| 接口 | 权限及用途 |
|---|---|
| GET /v1/menus/{code} | 已登录个人身份浏览已发布菜单，不含设备密钥、原始观测或他人订单 |
| GET /v1/me/orders | 本人订单列表与当前状态 |
| GET /v1/orders/{id} | personal仅本人；工作context需本场地角色，取餐码只返回本人 |
| POST /v1/orders | personal提交，菜单run、项目版本、数量；后台核价 |
| POST /v1/orders/{id}/actions | 本人取消／申请取消；厨房接受／拒绝／处理申请／开始配餐／确认配出／核验取餐，按动作和状态授权 |
| GET /v1/workspaces/{id}/orders | 本场地厨房队列，普通顾客不可读取 |
| GET /v1/workspaces/{id}/menu | 管理资料、可售与预留、菜单代码 |
| GET /v1/workspaces/{id}/menu-qr.svg | 获授权工作身份取得实际二维码 |
| POST /v1/menu-items/{id}/actions | 经理更新字段／发布／库存，版本与幂等保护 |
| POST /v1/workspaces/{id}/service | 经理修改供餐方式；开放订单或测量窗口存在时拒绝 |
| GET /v1/operations/{id} | 扩展到本人personal作用域，仍核对操作人和原context |

实际字段以Pydantic和运行服务的OpenAPI为准。经理菜单编辑带管理expected_version，供餐方式编辑带service_version；顾客订单行item_version对应quote_version。
