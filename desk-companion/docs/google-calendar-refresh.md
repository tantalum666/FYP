# Refreshing imported Google Calendar events

In **Calendar files → Google Calendar**, choose the dates of the local copies and select **Refresh imported events**. Review the changes and confirm or discard them. The last confirmed refresh shows the dates and counts. A refresh checks up to 50 imported entries overlapping a range of up to 31 days, with an exclusive end date. The separate **Preview date range** action can import new entries.

Each confirmed import associates its local event, last imported version and Google occurrence ID with the current OAuth connection. Refresh reads each associated ID from the primary calendar, so it can find a meeting that moved beyond the selected dates. A matching cancelled occurrence or an explicit `410 deleted` response offers the local copy for removal. A `404 notFound` can mean lost access. The review marks that copy unavailable and keeps it, including when other events change in the same batch. Older pending reviews that proposed removal without cancellation evidence expire and require a fresh read. [Google Calendar error guide](https://developers.google.com/workspace/calendar/api/guides/errors#404_not_found)

Earlier imports stored only a hash of the Google ID. When the desk has a single recorded Calendar grant and has never disconnected it, refresh can match those hashes from an ID-only list in the selected dates. It retrieves details only for matching IDs. An old event that moved or disappeared before its ID could be matched stays unresolved. Reauthorization creates a new grant version. Copies without verifiable provenance stay local, and a new date-range import can create separate copies for the current grant.

For an older copy that has changed locally since creation, the desk checks its saved Google preview and approval receipt. An approved replacement that accounts for the current version and contents establishes its import baseline. If that history is incomplete, refresh keeps the copy by default. The owner can select the proposed change for that individual copy after reviewing it. Known manual edits, occurrence exceptions and unsupported Google details stay on the desk. Editing a copy or confirming a newer review of it invalidates an older pending refresh.

Portable backups preserve each desk event ID. For a copy with a verified Google link, the export derives a distinct backup key from its grant, occurrence and desk ID. Restoring onto another desk creates detached local events. Importing from its connected account creates separately refreshable copies. Merging a backup into the original desk keeps its existing events and links.

The importer expands occurrences with time bounds and start-time ordering. Google restricts these parameters with a collection sync token. Range lists allow up to ten pages and 500 items. A 410 during pagination restarts the same range once. All pages, retries and individual reads in a preview share a 60-second deadline. An incomplete batch leaves the calendar and last confirmed result intact. The original operation key can recover a pending review for 15 minutes or the receipt for a confirmation or discard. Private review results appear only in the session and privacy context that requested them.
