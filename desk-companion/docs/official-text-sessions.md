# Group 2 · Ordinary OpenAI text conversations

On the source branch, ordinary OpenAI messages from the shared composer use the official Agents Sessions REST API and application-hosted Functions. Both the blocking and SSE routes share this implementation. The release last verified on Web, iOS Simulator and Pi is `c607759e`. [Previous deployment](../../output/qa/2026-11-18-three-end-rollout/verification.md)

## Conversation and authority

The first message creates a session with its initial input, the configured OpenAI model, `environment.type=none`, multi-agent execution disabled and a catalog of permitted FYP functions. The ordinary text session has no hosted computer or shell. Existing local answers, selected-file Responses requests, other configured providers and Live voice retain their respective paths. Sessions accept text and image input parts. The existing file feature supports document bytes including PDF and Office files via Responses with `store=false`. The app chooses that path before dispatch when files are attached. A Sessions failure never switches to a different provider. [Create session](https://developers.openai.com/api/reference/resources/beta/subresources/agents/subresources/sessions/methods/create)

A follow-up can reuse the same idle remote session when the authenticated local chat, selected task, prompt, source projection and authority still match. The app adds intervening local or voice turns and checks the new root turn separately. It rotates the remote context after private tool reads or action preparation. Local receipt replay survives a restart. Temporary conversation history retains its existing 30-minute lifetime. Hiding private context restricts new ordinary requests to the user's message and language without business tools. [Sessions guide](https://developers.openai.com/api/docs/guides/agents-api/sessions)

The application executes only advertised, currently pending function calls. The ordinary handler uses the existing typed registry, audit and effect keys. It binds a result to the same session, turn and call, sends it using `agent.session.input.tool_result` and verifies the matching completed final answer. Mixed parallel mutations are refused. A returned draft is recoverable even if the result acknowledgment is lost. The normal permission layer still decides whether a supported software draft can be applied. Mail sends and browser admission keep their existing owner decisions. [Functions guide](https://developers.openai.com/api/docs/guides/agents-api/tools/functions)

## Delivery, recovery and limits

The streaming UI receives final-answer text events and local tool progress. If an observer disconnects, the server checks canonical turn/items and pending actions. Historical tool-call items cannot dispatch a function. An uncertain initial create is located by an opaque metadata marker. A lost follow-up acknowledgment does not cause new input. Local cleanup receipts retain technical IDs and hashes for expiration, logout, forgotten conversations and failed deletion. Deletion completes after a GET returns 404. A crash before a local business outcome can be established leaves an interrupted receipt and suppresses automatic replay. A disk receipt alone cannot restore the owner's expired temporary login or chat.

The existing daily conversation/computer request cap covers initial input and function continuation. Each session also requests OpenAI's 25-US-cent service ceiling. This ceiling is cumulative across its turns. It is an implementation limit, not a funding authorization or an invoice. The source continues to honor the configured OpenAI credential and approved loopback transport. The cleanup worker only reconciles resources. Proactive model research retains its separate default-off switch.
