## Explicit review, separate authority

A signed-in, visible owner can select one server-observed input snapshot, review/edit it, then hand it to the existing Work composer. Freezing a snapshot neither starts work nor retains a conversation. A nearby person, playback, provider role label, final transcription or unchanged goal does not verify who spoke and cannot approve any action.

The initial interface ends voice only after an acknowledged draft and deliberate “End voice and review work” action. Work still needs independently selected evidence, current scope, an actual `retain: true` boolean and explicit start. The client blocks a first start after expiry, while preserving an already-pending original creation request and its operation ID for safe receipt recovery. The voice handoff defaults to deterministic evidence compilation; model mode requires its own exact text destination and selected-context sharing. Voice provider consent does not grant permission to a second work provider. No automatic source/memory/conversation selection, retention, provider reconnect, TTS status return, memory extraction or spoken approval is introduced.

Existing typed-goal behavior remains available when voice is unconfigured. An expired voice reference cannot silently become typed work. The owner must review a new snapshot or explicitly start an ordinary typed goal without asserted voice provenance.

## Server-observed input ledger

`backend/desk/voice_work.py` is owned by `VoiceService.work`. It contains volatile text only for actual authenticated owner sessions while private context is visible. Paired/controller/display/local voice-agent identities retain their existing voice paths but cannot obtain an owner input ledger or freeze/start Work. A raw opaque reference alone is not authorization; the actual live owner session cookie, original session hash, privacy revision and actual voice provider/model/destination must match.

Provider adapters produce private normalized `transcript` input updates with an explicit append/replacement mode, adapter-owned sequence, correlation key and boundary. Provider item IDs are untrusted correlation data and are hashed internally; public voice/session/segment/draft IDs are generated by the server. Unknown roles, malformed updates, stale sequence numbers and provider tools do not become input candidates. Invalid UTF-8 (including unpaired Unicode surrogates) is refused before sequence advancement, eviction or any segment mutation; the Qwen fallback correlation hash uses only validated transcript text.

- Qwen's existing completed-input-transcription event is a replacement with `provider_final`. A repeated identical item/final is deduplicated. A contradictory final makes that segment ineligible rather than rewriting it into another selectable candidate. Without a provider item ID, identical final text is conservatively correlated; this does not assert distinct speech turns
- Gemini input transcription chunks append within a local group and remain `unfinalized`. Interruption and assistant `turnComplete` separate groups without claiming user-speech finality. The owner freezes a visible text snapshot, not an inferred speech act
- Assistant text/audio transcription, tool arguments, silence, audio data, assistant completion and interruptions cannot freeze a draft or create a run

Client `voice_input` events are complete replacements, not raw deltas:

`{type, voice_session_ref, input_segment_id, revision, sequence, role: "user", text, operation: "replace", boundary, eligible, reason, provider, model, destination_id, observed_at}`

`boundary` is `provider_final` or `unfinalized`. `reason` is null or a bounded error such as `VOICE_INPUT_TOO_LARGE`/`VOICE_INPUT_INVALID`. Ineligible segments contain no text, and later fragments cannot turn an overflowing segment into a tail-only goal. The workspace voice snapshot exposes a non-authorizing `config_revision` fingerprint so a provider/model/destination change can also invalidate private client state; no credential is included.

## Bounds and lifecycle

There is one active ledger session. At most eight input segments are kept, with older segments evicted; a bounded 128-key correlation set prevents an evicted provider item from being revived. Reaching that session correlation limit ends input eligibility rather than allocating unbounded state. Each segment is at most 4,000 characters. Selected snapshots and live segments share a 32 KiB UTF-8 text ceiling per voice session, counting identical immutable revisions once.

At most four frozen drafts exist across the service. A draft expires five minutes after selection using both a monotonic deadline and the displayed wall-clock expiry; either expiration removes it, so wall-clock rollback cannot extend plaintext lifetime. Later freezes of that same acknowledged snapshot return the same reference without extending its lifetime. Disconnect immediately discards all unselected segments and keeps only explicitly frozen drafts for their remaining TTL, never longer than five minutes after disconnect. Cleanup runs on ledger operations and the existing Runtime tick. Transport teardown first stops tool-dispatch acceptance; ledger end is memory-only and clears unselected text without depending on SQLite. An unexpected ledger-end error cannot skip active-slot, dispatcher or socket cleanup. Session expiry/sign-out, hide/show, privacy revision and voice configuration changes invalidate the affected ledger/drafts. Restart loses all unstarted drafts.

No raw audio, unselected speech, assistant speech or provider tool arguments are persisted by this bridge. Transcripts do not enter logs, usage records, durable operation receipts, URLs or localStorage. Volatile-memory cleanup is not a forensic erasure or provider-side deletion claim. Legacy explicitly requested business drafts still have their separate existing retention contract.

## Freeze API

`POST /api/voice/work-drafts` accepts only:

`{voice_session_ref, input_segment_id, expected_revision}`

The actual cookie is taken from the HTTP request, not request JSON. Guessed/foreign references, a new owner session, hidden/expired owner, paired or agent principal and forged metadata are rejected. `expected_revision` must be a real integer. An unacknowledged changed revision returns `VOICE_INPUT_CHANGED`; an already frozen revision is immutable and its duplicate acknowledgment remains recoverable until expiry. The endpoint performs no provider call, external effect, run creation, durable write or source selection and is not advertised as a provider tool.

The response is:

`{voice_origin_ref, text, revision, boundary, provider, model, destination_id, observed_at, owner_reviewed_at, expires_at, snapshot_kind: "owner_snapshot"}`

`owner_reviewed_at` records the authenticated owner snapshot-selection time; it does not claim speaker verification or completed effect approval. The existing explicit Work start retains the subsequently edited goal.

## Atomic retained admission and retries

`RunCreate.voice_origin_ref` is an optional strict server draft reference. The goal remains the exact edited `goal` in the existing request. Extra client-origin metadata is rejected. Numeric `1` does not substitute for `retain: true`.

Existing committed operation receipt lookup occurs first, under current owner/private-read access. A matching original operation can recover its already-created run after draft expiry or process restart. Changed request content conflicts. A different operation ID for an already-used voice draft returns `VOICE_DRAFT_ALREADY_USED`; it never duplicates work. An unknown/uncommitted/expired reference returns `VOICE_DRAFT_EXPIRED` rather than falling back. Existing non-voice create request hashes remain compatible by omitting the absent new field from their canonical receipt input.

After normal bounded preflight, admission uses the existing run lock then personal-context lock → ledger lock → SQLite write transaction. It rechecks real owner/session/private visibility, privacy revision, current read-only scope, selected personal-context binding and exact voice snapshot/config. It atomically saves the run, normal creation receipt and a unique `agent_voice_origins` reference-hash claim. No network/provider I/O occurs inside these locks. Capture/freeze use short read snapshots and may linearize just before a concurrent hide/sign-out; the private client epoch fence discards a subsequently stale response, and no new retained run can cross the final current-authority transaction. They do not hold a database write lock for every audio transcript chunk. Failed admission rolls back all three records. The new final fence also closes the preexisting hide/scope-change interval between run-create preflight and commit; it does not broaden any action authority.

Only the final reviewed goal and minimal server-derived `voice_origin` are retained:

`{channel: "voice", provider, model, destination_id, observed_at, boundary, owner_reviewed_at, retained_at, edited, snapshot_kind: "owner_snapshot"}`

The public/durable run never contains the raw draft reference, original transcript copy, unselected neighbors, raw owner token or provider key. The claim stores reference/request hashes and run ID only. Hashes are integrity/deduplication metadata, not anonymization. Origin is neither evidence nor permission and stays out of model/tool payloads; only the reviewed goal and separately admitted selections enter planning. Existing run retention and deletion limitations apply to that final goal/results independently of discarded speech.

## Controls remain separate

Speech interruption and voice disconnect keep the existing voice proposal cleanup and physical-output stop priorities. They do not pause/cancel an independently retained Work run. Freezing a snapshot still does not steer. The review screen can then update one current run with that snapshot: the ordinary assistant message carries `voice_origin_ref` and `voice_steer: true`, and `ConversationWork.turn` steers. One current run is the target. Several require an explicit run. None keeps “End voice and review work”. The same turn shows a byte-verified report file for the new goal, without claiming the real-world goal was achieved. See [conversation goal changes](conversation-work.md). Work pause/cancel still use the selected run's authenticated versioned controls and their original unknown-effect/no-rollback semantics. Speech playback suppression belongs to the client audio lifecycle; a local mute is not proof of remote model cancellation. No provider-callable work start/approve/pause/cancel or owner-answer tool has been added.
