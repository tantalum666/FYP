# Live flight offers and an owner-approved LetsFG booking

Alice connects the owner through **Device → Apps & devices → LetsFG Flights → Connect**. The provider is the official LetsFG public agent service. Its OAuth consent grants flight search and booking; the owner approves a specific itinerary, passengers, currency, and amount separately in Alice. Card enrolment and any bank approval use the payment provider’s own interface. FYP does not receive a card number. [LetsFG agent guide](https://letsfg.co/for-agents) · [Official MCP/OAuth documentation](https://letsfg.co/developers/docs/mcp/).

## What an offer proves

For a new itinerary the text Session uses the read-only `live_flight_search` Function. An explicit choice of either airport searches each accepted route with the same date, party and bag request. A selected result stays bound to its exact original supplier query. The card shows the fare while a checked-bag total is unverified; a changed total goes back to owner review. A disconnected desk can retain the request and connect the supplier. [Conversation and receipt checks](../../output/qa/2026-11-26-airport-choice-and-reminder/verification.md).

The desk identifies itself on authenticated public-agent requests. The supplier can return a completed status while price enrichment or split-ticket checks are pending. The original search is polled until those flags clear. The desk honors a supplied expiry even when the provider still calls the cached result completed. A new login can bind a cached identifier only after its own authorized search returns it. A prior login keeps its existing binding. A settled offer shows a published fare even when the requested baggage-inclusive price remains open. A result page uses the supplier’s agent-channel link with both the search and offer identifiers. Without its channel parameter the website can start a general route search. The existing read-only seller check opens the specific itinerary. Live connector and public-page prices differed during the 24 November ordinary-account check. Each figure belongs to its channel and time. [Live supplier evidence](../../output/qa/2026-11-24-continuity/verification.md) · [official public-agent client](https://github.com/LetsFG/LetsFG/blob/main/sdk/python/letsfg/local.py).

The agent API prices each seat for the whole trip. For a return journey, Alice matches every outbound and inbound segment, dates, airports and any known flight-number sequence and airport-local times. The returned fare is multiplied by seated adults and children. A lap infant does not count as a seat. A missing return, conflicting offer identifiers, or an uncertain flight combination cannot establish the buyer’s requested itinerary.

A fare research result, including Kiwi’s displayed amount, carries no LetsFG search or booking authority. Search and reprice the specific LetsFG offer on its connected account. For a requested checked bag, the standard agent offer guarantees no weight field. Alice accepts a concrete supplier-attributed inclusion rule only when the statement gives the count, weight, party or per-passenger coverage and all-flight coverage. A per-bag estimate remains separate from the payable total. For the original HK$3,389.59 research result with an unverified 20 kg allowance, Alice can open the original seller and ask for the bag-inclusive price. [Published agent fare fields](https://letsfg.co/for-agents) · [Supplier terms on baggage and extras](https://letsfg.co/en/terms).

## Submitting, recovering and cancelling

An owner-only coordinator can call the live adapter with a stable approval ID, freshly checked source offer and owner-confirmed passenger information. One supplier POST covers the party. A price or material itinerary change returns another review before any submission. The provider exposes no documented live booking lookup by client-generated idempotency key. The desk commits a reservation in its existing operations journal before making the request. A lost acknowledgement blocks another submission for that review and prevents a second automatic hold. A returned booking reference is encrypted with the desk’s existing Vault and an app-local handle is returned to the coordinator.

An initial hold is identified by its currency and amount. Completion requires a separate authenticated status read for the original booking, a PNR, and a matching captured amount in the approved currency. An uncertain response, new supplier question, different currency, bank approval or card setup remains actionable in its own state. For flight cancellation, the original supplier’s fare rules apply. The published stop endpoint belongs to the separate test service. The live adapter’s cancellation inquiry only reads the booking and directs the owner to the supplier. [Official live booking states](https://letsfg.co/for-agents) · [Fare and cancellation terms](https://letsfg.co/en/terms).

On an eligible first booking, LetsFG can return `payment_method_required` with the signed-in account’s own `add_card_url`. The owner completes the provider’s zero-value card setup there, then returns to Alice for a new fare check and confirmation. The same supplier login can be used. An agent price and a website price can differ for the same flight. A checked-bag counter with no weight or fee does not establish a payable total. [Original-device and seller readback](../../output/qa/2026-11-26-pi-return/verification.md).

## Operator configuration

Loopback callbacks work on the same desk. A user opening consent from another device needs a browser-reachable HTTPS return path. Set `DESK_LETSFG_REDIRECT_URI` to the exact hosted `/api/apps/letsfg/callback` URL, or supply the deployment’s `DESK_PUBLIC_ORIGIN`. The public client registers automatically from an authenticated FYP connection request. A refresh credential is reserved before rotation so an uncertain network result cannot replay a refresh token and revoke the whole grant. Owner reconnection is available if the rotated token cannot be recovered. The access and refresh tokens, PKCE verifier, and supplier booking reference stay out of model tools and public receipts.
