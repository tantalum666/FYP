## 使用者现在可以做什么

1. 在Tasks创建事务：标题、截止时间、进行状态、等待原因、下一步、步骤、展示隐私、跟进开关和下次检查。
2. 记录后续进展，跨会话保留同一事务和历史。勾选步骤只改变步骤，整体完成需本人单次确认或适用的完整权限策略；勾选步骤本身不会完成事务。
3. 到检查时点出现一条待跟进提示。没有新回应时保持这一条，不持续叠加；本人可更新、延后一小时、暂停、完成或取消。
4. 从事务打开助理，检查进展草稿后保存；从事务准备日历时段，另行检查开始／结束时间后保存。截止、工作时段与完成三者独立。
5. 在电脑／手机管理页查看Tasks和Today摘要；独立常亮屏只加跟进数量入口，触摸展开事务面板，保持大时钟与月历构图。

主预览：`http://127.0.0.1:5190/?page=tasks`；同源构建：`http://127.0.0.1:8831/?page=tasks`。界面中英文可切；演示与测试数据只放隔离QA库。

## 保存、调度与完成依据

`tasks.py`保存tasks、task_evidence、task_followups。每次用户操作带操作ID与预期版本，重试不重复创建，过期版本拒绝覆盖。一次事务最多20个步骤，工作空间最多500件事务。

- 状态为To do、In progress、Waiting、Completed、Cancelled。Waiting必须有等待原因。
- 日期使用事务的IANA时区，拒绝无效和夏令时歧义；指定检查必须在未来。默认间隔可选1小时／4小时／1天／1周；API允许15分钟至7天。
- 未指定检查时点时，用默认间隔或更早的未来截止。明确延后／恢复按指定间隔执行，已逾期仍有逾期标记，不篡改原截止。
- 一秒本地调度只检查到期条件，不调用语言模型。待跟进内容落盘；服务重启后保留、合并，不重复生成同一版本的提示。
- 安静时段内不新建跟进提示，也不把已排队的可选文字建议发给模型。到期时间改到安静时段结束，并记在 `task_quiet_holds`。默认安静时段是 22:00–07:00（工作空间时区）。服务重启后这条推迟还在，不会再生成第二条。声音开关仍然只决定提示音，不决定是否出现这条提示。
- 拥有者改保存的安静时段后，下一次调度按新偏好执行。仍在安静时段内，就把推迟改到新的结束时间。已经不在安静时段，就把原先被推迟的事务放回提醒队列，仍每次最多 3 条。本人指定的未来检查，以及延后／恢复后的时间，不会被提前。全天安静（开始与结束相同）把推迟稳定记到下一个本地午夜，避免每秒改写。
- 同一次检查最多新建 3 条跟进。其余到期事务各推迟 1 分钟，避免长时间离开后一次弹出全部提醒。关闭跟进的事务不再留在到期队列里。
- 更新、进展记录、延后、暂停或结束会解决旧提示。进展记录保留用户原意，不从措辞自动推断整体完成；状态与下一步可通过编辑或模型草稿另行修改。
- 手动完成来源为`user_confirmed`；完整权限下的新请求自动完成记为`owner_policy`，界面明确区别。没有网页提交系统或真实交付回执，不能写“系统核实提交”；从备份恢复的完成来源另标`backup`。
- 普通提示音复用安静时段和一次领取机制，只播泛化提示。声音不开启时仍有屏内入口。应用关闭且本地API停止时不继续运行；这是本机后台，不是云端常驻服务。

## 文字与语音AI

默认`DESK_TEXT_PROVIDER=none`，规则模式可用`Track: finish the report`／`跟进：完成报告`建立草稿；在选中事务中输入进展保存为记录，输入完整的done／已完成可生成完成草稿。界面明确标注本地规则，不宣称已理解任意自然语言。

可选文字模型支持Qwen或Gemini，与语音配置分开。两个供应商是 `text_providers.py` 里的适配器，由配置选择；调用方仍走 `TextAssistant.generate`。API密钥留后端，不进入客户端或业务备份；模型型号由使用者根据已获准服务填写，无默认付费型号。端点白名单、JSON解析、类型校验和允许工具限制共同控制调用。切换供应商不需要新的作业或跟进代码。在有花费上限之前不要开通账号。

- 单次文字请求最多三步，步骤间超过 45 秒即停。读取可以继续；草稿、作业取消和软件停止只执行一次。提供方临时失败或无法使用的回复在该步工具之前最多共试 3 次，然后给可读说明，不重放已执行的工具。语音工具调用走同一策略。模型没有确认接口。对话调用另有 `DESK_TEXT_DAILY_CAP`（默认 40 次／UTC 日，含失败和重试）。见[代理循环](agent-loop.md)。
- 上下文取保存的事务、选中事务近期历史及有限日历窗口；不自动读取邮箱、全盘文件或屏幕。
- 已保存的文字回复／草稿按操作ID去重；不保存原始录音。确认的进展成为明确事务记录，不能把全部语音转写悄悄作为长期记忆。
- 可选`DESK_TEXT_BACKGROUND=1`仅给已产生的检查补充建议，不修改任务状态或驱动机械。默认关闭；自动请求每天最多20次，失败尝试也计数，超时或失败保留本地提示。重启不重试已开始但失去结果的请求。
- 背景建议发布前再次检查版本、暂停和完成状态，旧任务建议不能覆盖新进展。
- Qwen Audio与Gemini Live已有语音通道复用相同事务工具。自然度、回声、打断及真实工具提取能力仍待真实API和麦克风验证。

已核对官方接口：[Qwen结构化输出](https://help.aliyun.com/en/model-studio/qwen-structured-output)、[Gemini结构化输出](https://ai.google.dev/gemini-api/docs/generate-content/structured-output)。本轮只执行httpx模拟协议测试，没有付费调用或模型优劣结论。

## 数据与隐私

本人批准的手机／电脑共享同一个工作空间。私人标记是展示政策，不是新增多用户权限；公开分享不包含事务。常亮屏请求`display=true`服务端投影，开启离桌隐私且姿态缺失时隐藏私人事务详情；前端在连接陈旧／断开时同时隐藏私人缓存。主屏入口只显示数量。

已打开的私人事务记录／编辑草稿在隐藏期间保留在当前页面内存中，遮住输入，返回后可继续；主动放弃或关闭页面仍会丢失未保存内容。新建表单为本人触摸输入，不用于显示已保存私人资料。未保存内容有退出／页面切换保护；忙碌请求不允许关闭窗口造成误认未保存。

业务备份包含事务与每件最近20条进展，界面注明范围。合并恢复保留现有事务，不覆盖较新进展；新增的恢复事务默认暂停跟进，避免一次唤醒多件旧任务。旧版不含事务的备份仍可读取。SQLite原始备份可能含认证数据，另存在私有运行目录，不能当普通分享文件。

## 2026-10-06 执行作业关联

事务详情现返回关联作业的安全状态／校验元数据，全文仅在拥有者电脑作业审阅API返回。可从事务助理准备专用目录笔记；任务版本变化、结束或取消会阻止旧写入意图批准／开始执行；29日允许以当前版本准备终态事务的新只读核验。按task_id先筛选，再对未解决作业优先分页，避免其他任务的新记录掩盖旧结果。作业成功不自动完成事务，也不说明第三方应用任务已经完成。作业记录已进入业务 JSON 备份；笔记文件本身仍在本机目录，不随 JSON 复制文件字节。私有 SQLite 备份仍需操作人员妥善保护。

日历上下一个 30 到 180 分钟的空隙可以提出一条未完成目标或事务，并写明原因。空档不等于本人有空。没有落在这个窗口里的定时日程时，改为提出一条未完成事项：未回复的跟进、七天内到期的目标，或至少两天没有更新的事务。同一种建议关闭三次后暂停，主人能看见并清空。安静时段不提出。没有模型调用。

## 2026-10-27 提醒原因与检查

跟进仍由 `tasks.tick` 产生，不另建调度。每条待跟进带 `reason_en`／`reason_zh`：写明是因为到了已保存的检查时间、事务仍开启，若曾被安静时段推迟则写明是安静时段结束后才出现。私人投影不带下一步或标题。可选文字建议可以改写跟进正文，但保留这条原因。

早晨简报继续使用 `daily_brief_enabled` 与 `daily_brief_time`。晚间检查是同一份偏好上的 `evening_check_enabled` 与 `evening_check_time`，默认关闭。两者都调用 `is_quiet`：安静时段内不产生，保存时间之后的两分钟窗口内各产生一条，重复 tick 不新增。拥有者可在偏好旁看到原因和数量摘要并关闭；这不是按事务再发一条跟进。屏幕提示音沿用同一次领取，晚间一条播报原因。没有模型调用。记忆上的早晨核对是另一件事：拥有者批准后，由记忆跟进的同一次规则 tick 把多条到期跟进合成一条，契约见 [memory-followups.md](memory-followups.md)。它不改这里的简报时间，也不另建调度。

新的一条简报或跟进会交给 `desk/notify.py` 的三个通道：打开的页面收件箱、浏览器 Notification 可用的 Web Push 形状载荷，以及设备提示音队列。安静时段三个通道都不投递。同一个通知 id 每个通道只投递一次。设备领取会占用原有的 `brief/`、`evening/` 或 `task/` id，避免同一件事再播一次。本机不联系推送服务。

## 2026-10-27 目标

“Goal: … by Friday”、`我要周五前…` 这类句子只准备事务草稿。确认后才写入目标和跟进；取消则什么都不记。跟进用截止当天上午，若上午已过则用截止时刻。到期后每个本地日准备一次完成草稿，确认前目标保持未完成。这些目标列在“我了解的你”页面。没有模型调用。
