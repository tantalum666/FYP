# LetsFG test bookings in Alice’s ordinary conversation

An owner can ask Alice to book one fictional adult on a one-way base fare in HKD. Supply the airports and date. A flight number, airline, nonstop requirement or maximum HKD total narrows the search. If the sandbox has no exact match or cannot verify a required checked weight, Alice asks for a change. A real-market price lookup continues through the existing public research tools. ## Hong Kong fare amounts

An imported Kiwi result supplies its currency and integer minor units. Chinese chat and the quote card show a listed amount such as **HK$3,389.59**. Mandarin and Cantonese read the same amount as **三千三百八十九点五九港元**. A zero directly after the decimal is spoken when it changes the amount. Baggage and final checkout totals retain their own verification status.

A Chinese fare readback sends the verified amount into the owner's existing Live voice session. The desk buffers that utterance before playback and compares the provider's caption with the expected decimal wording. It releases the original PCM for a match. An uncertain or mixed-unit attempt can request one correction in the same session, followed by the written price if the wording remains unconfirmed. ## Owner journey

1. Type a request in the ordinary composer. For example, “帮我用 LetsFG 订 11 月 25 日香港 HKG 到东京羽田 HND 的 FR4315 测试机票，一位成人，无托运行李。先给我看总价。” Specify the year when it is ambiguous. To exercise an increase, explicitly ask to rehearse a mid-booking price change.
2. Alice’s official Session can call one application Function, `sandbox_flight_quote`. It searches the fixed sandbox endpoint using only route, day, party size and currency. The card shows selected segments, local dates/times, passenger count and the displayed HKD total. This phase creates no supplier order. The owner can confirm or cancel on the card and can answer in the current composer.
3. The server ties the decision to the signed-in owner, chat, review version and amount. It saves the approval before posting the provider’s fictional passenger and a stable idempotency key. The provider supplies its simulated Visa. Full software access still requires confirmation for each price.
4. If the provider asks about an increase, Alice shows the old and new totals and the supplier deadline. A fresh provider read must still match that round before a new decision can be sent. The owner may decline. A missing answer can expire and release the hold. Increases requested for a rehearsal use the provider’s human-paced scenario.
5. The conversation polls the original booking. It shows a reservation reference and simulated charge only after a terminal sandbox record matches the selected offer, currency, approved charge and test card. The displayed hold can differ from the final approved charge. Ask Alice for the test booking reference or payment result to reopen the conversation’s verified record.

## Missing flight and stopping an order

If the named flight is absent, Alice can show up to three eligible alternatives from the same sandbox search. Their dates, airports, direct-flight and fare constraints remain in force. Selecting one requests a fresh quote with its own owner approval. A search and a list of alternatives create no order. A real Simulator selection of the second option AF3258 returned a fresh HK$55 approval card without creating a supplier booking. When a chat contains multiple orders, use the original booking card or identify the flight, for example “查回航班 AF2979 的取消结果”.

The ordinary chat can stop a booking that is already underway. A stop response can be immediate, pending, too late, or referred to a person. Alice checks the original supplier booking for a terminal release, charge and PNR. A captured ticket remains subject to the seller's fare rules. The owner can revisit a stopped or completed order in the original chat after a backend restart. [Simulator and provider acceptance](../../output/qa/2026-11-21-commerce-aftercare/verification.md) · [LetsFG stop contract](https://letsfg.co/developers/docs/api-sandbox/index.html#5-stop-a-booking).

Available flights appear as compact time-and-price rows. Tapping a flight asks the ordinary Session to recheck its route, date and applicable budget. The newly returned quote still requires the owner's decision. The running desk can read an in-progress booking or a new price while the conversation is away. It never submits a booking or answers a supplier question from that worker. [Order presentation and follow-up](../../output/qa/2026-11-21-quiet-order-followup/verification.md).

## Flights that fit the desk calendar

Ask Alice to avoid calendar conflicts, for example “查香港去东京羽田的直飞航班，不超过 HK$50，避开我的桌面日程”。 The comparison uses the owner's locally saved calendar and the same ordinary Session quote Function. If the named service overlaps a busy entry, Alice can offer other verified choices within the route, carrier and budget. A selection is a fresh quote. With no named flight, the lowest-priced verified fit among the returned eligible offers is proposed.

Calendar matching covers departure through arrival, including connections. Each endpoint uses its published offset when present or its airport’s IANA zone. The desktop calendar supplies busy, incomplete occurrences with its recurrence, exceptions and all-day rules. Endpoints that merely touch are compatible. An unresolved local time, including a clock-change fold or gap, cannot be shown as clear. When reported duration and local endpoints disagree, the calendar must be clear for both possible ends. No ground-transfer allowance is assumed.

The owner’s selected itinerary and price cap remain bound across a re-quote. The app rechecks the calendar inside the transaction that admits a booking or a price increase. A new conflict keeps the approval unsent. “查其他航班” on a blocked, unsubmitted quote uses the existing search to find a different matching service under the original constraints. A removed calendar conflict can make a current review actionable again; a fresh owner decision is still required. A held or purchased booking follows its original supplier process. Calendar titles, event identifiers and busy intervals are not part of the supplier search request. ## Implementation

The existing Sessions dispatcher prepares the quote; no model tool grants spending authority. The normal message endpoint processes owner decisions and the existing conversation refresh updates the card. A single SQLite table stores the chosen quote, versions, decisions and upstream reference. A lost submission acknowledgement can be recovered with the same request key. An uncertain answer queries the existing booking. An unmatched capture stays unverified. A recovered owner conversation can re-open its local record. Explicitly forgetting a conversation removes its association with the provider record. [Official OpenAI Functions](https://developers.openai.com/api/docs/guides/agents-api/tools/functions).

The installation opt-in is `DESK_LETSFG_SANDBOX_ENABLED=1`. There is no configurable live payment endpoint or field for a real card, passport, wallet or traveller. Booking IDs on the public sandbox can be used to read its records, so they stay private. The operator verifier takes the original quoted amount and, for an accepted price change, an optional independently approved `approved_charge_amount`.
