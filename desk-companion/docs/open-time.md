# Open time in the conversation

11 November 2026. Grok Bot, offline. Alice answers one asked question from the saved calendar: when the owner is open, or whether one clock time works. This is a gap on the saved calendar. It is not a claim the owner is actually free, and it does not create, move, or book anything.

## Why this, and not another card

The research index’s life journeys are mail, a staple purchase, and a trip. Those, plus Work re-show and continue, the folder-job clock, browser takeover, memory follow-ups, the morning check-in, trip quotes, saved and scheduled skills, the staple purchase card, cited briefs, held choices, and the asked “what should I do next?” sentence, are already open pull requests. Codex’s pull request owns the shared Alice home, attachments, Gmail and Outlook drafts, and voice preferences.

What is still missing in an ordinary conversation is the question a person actually asks when someone wants to meet: “When am I free tomorrow?” The calendar list answers “What is on today?” by naming saved events. A nudge may use a 30–180 minute gap for an unsolicited task, and it stays silent in quiet hours. This question is asked, so Alice answers. Quiet hours and proactivity off do not suppress it.

## What the owner can say

The whole message has to be the question. English and Chinese both work. The reply language follows the request.

- “When am I free?” and “Am I free?” use today, 08:00–21:00, in the owner timezone.
- “today”, “tomorrow”, “this morning”, “tomorrow afternoon”, “on Thursday”, and “next Thursday” pick the day. A bare weekday is the soonest one, including today. “next Thursday” is seven days after that soonest weekday. The reply always names the calendar date.
- Morning is 08:00–12:00, afternoon 12:00–18:00, evening 18:00–21:00. A missing part of the day stays 08:00–21:00. A missing clock lists openings. It is not turned into 09:00.
- “Does Thursday at 15:00 work?”, “Am I free tomorrow at 3pm?”, and “明天15:00可以吗” / “明天下午3点有空吗” check that minute.
- “When am I free next week?” stays the existing calendar list. “What is on today?”, “What should I do next?”, a task title, and “Tomorrow 15:00–16:00 Studio time” are not this question.

An opening is a gap of at least 30 minutes between busy events, clipped to now when the window is today. A shorter remaining stretch is described, not offered as a meeting. A transparent event does not block. An all-day busy event that covers the window blocks the day. A weekly event blocks the later occurrence too. A time that has passed, or that sits outside the named part of the day, is said to have passed or to be outside. Nothing is written.

## Privacy, receipt, and provider

Titles come from the existing calendar snapshot. A private event is named for the owner only when the calendar is not hiding private events. A paired display hears “a private event” and still hears a displayable title. A request with no session is refused and does not contain those titles.

The same operation id returns the stored sentence, including after the calendar changes. A different message under that id conflicts and does not replace the sentence. A new id reads the calendar again. If the reply insert is interrupted, no receipt is stored and the calendar is unchanged; repeating the same id then answers. An omitted language stays English. An unknown field is rejected. A configured text provider is not called.

The answer is registered after memory, goals, and recall, and before a selected task would treat the sentence as a progress note. `Runtime.tick` is unchanged. No import was added after `from .goals import GoalService`. `mailbox_bundle`, `shopping_bundle`, and `offline_calendar_bundle` are unchanged. Schema version stays 3.
