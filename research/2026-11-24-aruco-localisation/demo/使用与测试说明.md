# 五块 ArUco 定位牌电脑演示

最新：三牌改为 L 形简单记录，主界面只填 A、B 两段厘米中心间距，无需手动 X/Y。点“桌面标定”开始，见《L形三牌记录说明.md》和《三牌测量记录卡_空白.txt》。保存后自动切到厘米显示；默认免测量模式仍可用。

新增：长深自动换算四角码心、桌面范围、未知物品变化检测、ID 4 接近障碍及越界提示，见《桌面范围与障碍提示说明.md》。

## 有界面的定位台

当前默认“免测量演示 · 像素轨迹”，无需测纸牌位置。先阅读《免测量演示说明.md》。下文桌面尺寸及参照中心配置仅用于切换后的“桌面定位 · 毫米坐标”模式。


新增功能：手机实时接入及五牌坐标见《手机实时定位与三牌备用.md》，水杯/电脑等检测见《桌面物品识别说明.md》。共享 GitHub 版提供模型来源与许可证；首次运行 `.venv/bin/python download_model.py` 下载并校验权重，再启动 app.py。Python 依赖保持 OpenCV。


Mac 双击 `启动定位台.command` 打开本机定位台。原项目电脑的 OpenCV 环境已装好，其他电脑须先安装依赖并下载模型。页面提供开启／关闭摄像头、导入本地图片／录像、运行生成样本、暂停／继续、修改桌面标定、录制测试和导出 CSV。

点“桌面标定”，可用 L 形三牌只填两段中心间距；高级选项仍可填写桌面长深和四个参照码的实测中心坐标。点“开启摄像头”后按浏览器提示授予相机权限，或直接“导入录像”。处理画面会标出 ID 和边框，桌面图显示 ID 4 的位置、朝向及轨迹。丢失参照或目标时，位置显示不可用。

点“录制测试”后，识别画面、轨迹图和坐标会一起录入视频，再点“结束并保存”下载。暂停、切换输入或应用新标定也会结束本次录制。CSV 从“导出 CSV”下载。生成样本保留 SYNTHETIC 标签。浏览器根据支持情况保存 MP4 或 WebM。

关闭终端会结束本机服务。重新双击启动文件即可再打开。其他电脑首次使用时先按下文安装依赖，再运行 `python app.py --open`。程序只监听本机 `127.0.0.1`。

可先用已有电脑和摄像头完成图像采集、五个 ID 识别、桌面坐标和第五块牌的位置／朝向跟踪。用手移动 ID 4 作为目标。后续机械臂到货时，再验证它的实际相机接口、视野和画质，并把 ID 4 安装到 Mini。此包包含本地原型，首次实物测试需在你们的设备上运行。

定位模块由 Xu Ziqian 负责，包括运行和调整定位程序、摄像头与定位牌布置、坐标标定、位置和朝向测试、结果记录，以及 initial report 的定位部分。先按下文跑通生成录像，再接摄像头测试实物牌；每一步保留对应结果。

## 准备与摆放

电脑运行 Python 3.11 或 3.12。用电脑摄像头或已有 USB 摄像头，画面须同时看清四角码和移动目标。笔记本内置摄像头可先对小范围测试，能否覆盖 150 × 65 cm 整桌由实际视野决定。如果桌面远端的 40 mm 车顶码看不清，调角度、光线、取景距离和分辨率后再测。

摄像头固定、尽量俯拍。固定拍摄分辨率和焦距。先只在画面范围内摆四块参照牌，待能稳定识别后再扩大范围。学校打印的牌使用黑白双色，码面平整，保留白边，防止高光和手指遮挡黑框。五块牌先平放在桌上，图案面高度相同。ID 4 图案在生成时的上边作为目标前方，在白边旁用可移除标记提示方向。

整桌默认 1500 mm 长、650 mm 深。靠操作者左桌角为原点，长边向右为 X，向远侧为 Y。

| 牌 | 默认码心坐标（mm） | 用途 |
| --- | --- | --- |
| ID 0 | (50, 50) | 近侧左参照 |
| ID 1 | (1450, 50) | 近侧右参照 |
| ID 2 | (1450, 600) | 远侧右参照 |
| ID 3 | (50, 600) | 远侧左参照 |
| ID 4 | 手动移动 | 目标位置与朝向 |

这些坐标指黑框的中心，须用尺实测后填入 `layout.json`，不要把码中心直接写成桌面四角。小范围测试也需修改桌面尺寸和四个码心坐标。黑框不是含白边的牌外沿。默认沿用 `DICT_4X4_50`，ID 0–3 黑框边长 60 mm，ID 4 黑框边长 40 mm。

## 安装与运行

在解压后的目录打开终端。macOS 或 Linux 使用下列命令。首次安装需要网络，日后相机识别在本机运行。

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python aruco_demo.py --source 0
```

Windows 使用 Python 3.11／3.12，终端命令为

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe aruco_demo.py --source 0
```

按系统提示允许运行终端或 Python 使用摄像头。若选错镜头可试 `--source 1`。两个窗口分别显示相机识别画面和桌面坐标图。按 S 保存证据截图，Q 或 Esc 结束，关闭后在终端显示结果目录。识别成功后移动 ID 4、原地旋转，然后遮住和移开遮挡观察恢复。轨迹灰线记录检测历史。

包内有标明 SYNTHETIC TEST INPUT 的生成录像，可以先检查安装和界面。它用于测试程序，实物报告需使用真实定位牌重新采集。

```sh
.venv/bin/python aruco_demo.py --source synthetic_input.avi
```

自己的已录视频可用相同处理入口，例如

```sh
.venv/bin/python aruco_demo.py --source tabletop.mp4
```

摄像头开始时系统会决定实际分辨率，程序的 1920 × 1080 是请求值，实际值写在 `summary.json`。先查看能否清楚读全五个 ID，量测时保持拍摄设置一致。

## 记录的结果

每次生成独立的 `runs/时间戳/`，内含 `positions.csv`、`summary.json`、本次布局、最后一帧和按 S 取得的截图。CSV 中的位置单位 mm，朝向 0° 向桌子远侧，90° 向右，180° 向近侧，270° 向左。

| 画面状态 | 意义 |
| --- | --- |
| TRACKING | 四个参照和 ID 4 当前均可用，显示位置 |
| WAITING_REFERENCES | 当前未看清四个参照，坐标暂不可用 |
| TARGET_LOST | 四参照齐全，ID 4 丢失，坐标暂不可用 |
| DUPLICATE_ID | 同一个关键 ID 出现多次，坐标暂不可用 |
| INVALID_GEOMETRY | 参照几何退化或无法使用，须检查摆放 |
| OUTSIDE_TABLE | 计算的目标码心超出设定桌面范围 |

位置丢失时 CSV 坐标留空，灰线仍保留之前的轨迹。`summary.json` 统计所有处理帧中五个 ID 同框出现的比例，这一比例是当次输入记录统计，需结合遮挡安排解释。处理 FPS 代表电脑处理吞吐量，不能直接填作机器人控制时延。

## Initial report 的实测安排

下表是建议测试设计。认可阈值由老师与组员根据演示要求确定，测试后填写结果。

| 测试 | 怎么做 | 记录什么 |
| --- | --- | --- |
| 单牌识别 | 五块牌依次入镜，各停 10 秒 | 实际 ID、漏识别、误识别；四参照缺失时坐标会留空 |
| 整桌同框 | 四角固定，ID 4 放中间，录 30 秒 | 五码同框帧数／总帧数，实际分辨率与光照 |
| 定点位置 | ID 4 分别放桌面中央及四个内部点，用尺量码心，每点停 10 秒 | 每点真实位置、CSV 有效帧均值、位置误差及静止抖动 |
| 朝向 | 同一位置依次朝 0°、90°、180°、270°，每向停 5 秒 | 朝向误差；跨 0° 时用圆周角差计算 |
| 轨迹 | 手动沿直尺、矩形或 S 形路线移动 ID 4 | 覆盖区域、轨迹中断和恢复，手指避免遮挡黑框 |
| 遮挡恢复 | 分别遮住 ID 4 和一个桌角牌，停 2 秒后移开，各重复 3 次 | 是否立即显示丢失状态；从移开到首次有效识别的录像帧数 |
| 光照与距离 | 选正常光和侧光两种条件，或两种固定拍摄距离 | 相同安排下的识别比例和位置误差变化 |

码心位置误差采用 `sqrt((x测得-x真实)^2 + (y测得-y真实)^2)`，填写各点的平均误差、最大误差和有效帧数量。角度误差采用 `abs((测得角-真实角+180) % 360 - 180)`。手动移动路线用于展示跟踪，直尺和静止位置用于误差测量。

建议保留一次连续演示录像、原始 CSV、测量照片和一张实测结果表。先展示五个 ID，再展示位置、转向、轨迹和遮挡恢复。报告中可以将这部分写为 “Camera-based ArUco localisation prototype”，并注明使用手动移动目标验证。

## 当前适用范围

该原型用四个参照码的对角线交点确定码心，并在每帧重新计算平面映射，得到 ID 4 的桌面位置和二维朝向。参照短暂缺失时停止输出当前坐标。图像未做镜头畸变标定，偏斜拍摄和画面边缘需用实测误差评估。五块牌图案面应近似同高；ID 4 抬到 Mini 顶盖后，须使用相机内外参及实测码面高度做修正，再验证定位精度。

ArUco 牌本身是被动视觉标记。当前测试提供 IoT 系统的视觉感知与定位证据。若老师要求联网演示，可在定位程序中增加本地网络输出，将 ID、坐标、时间戳和有效状态传给另一台电脑的监控页，再单独验收数据传输。实际小车驱动、无线回座与整机控制需后续硬件验证。

技术资料采用 [OpenCV ArUco 检测教程](https://docs.opencv.org/4.13.0/d5/dae/tutorial_aruco_detection.html)、[平面单应变换教程](https://docs.opencv.org/4.13.0/d9/dab/tutorial_homography.html)及 [OpenCV Python 安装说明](https://pypi.org/project/opencv-python/)。
