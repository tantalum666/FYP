## Defects found during integration

- Several sibling PRs each replaced the same view handlers and each expected other actions to be absent. The combined contract gives Inbox, Home and source links distinct read actions, checks the selected item, preserves drafts and retains the opened Sources disclosure. A late calendar read cannot replace a newer or hidden view. The desktop and phone routes use the same target mapping. A followed-mail receipt resolves the current linked task from its bound thread, including older receipts that only stored the notice ID.
- A withdrawn suggestion could repeat information the owner had deleted. Removed private wording and links are excluded from the withdrawn item. Its generic acknowledgement is distinct from a historical Gmail suggestion whose source has been positively reverified. Follow and snooze require current authority. An explicit Inbox dismissal clears only still-bound members.
- Reusing the old notice ID could suppress a requested later reminder. The released snooze now has its own delivery identity. The check verified distinct original and deferred receipts, an unchanged source, and no duplicate after another scheduler tick.
- Reading an unavailable mail item could record that it was opened. The current owner, source account and thread are checked again after successful retrieval and before a replay. The original body is returned to its authorized view. Saving a reply draft does not send it. The isolated sample mailbox and the real connected account have different labels.
- The local browser worker could tear down the Playwright transport before confirming Chromium closed. The driver now stays alive through cleanup. Every owner input must still target the same document. An identical retry never types a second time, captured editable controls are masked, and private session storage is excluded from disk during an external handoff. The public read-only driver does not accept typed passwords or payments. Owner-entered sample values were exercised in the built-in rehearsal. The existing managed provider remains the route for supported external authentication.
- Test-specific ports had accumulated in production request policy. The trusted default remains narrow. The compiled UI checks explicitly supply a loopback fixture origin and write their output in a test directory. Assertions that sibling features must be absent were replaced with behavior checks. A genuine source forgery, unrelated task, stale selection, duplicate write, stale account or forgotten evidence still fails its own assertion.

## Always-on operation and spending controls

The normal Mac runs the existing launch-supervised desk. A process-bound idle-sleep assertion permits the display to turn off and macOS to lock while the desk continues to work. Turning off proactivity, ending the configured period or stopping the service releases the assertion. Physical shutdown, explicit system sleep and loss of network still interrupt external checks.

New notices enter a durable per-destination delivery queue. The original action and queue entries are committed together. Acknowledged recipients are skipped, transient failures back off, and withdrawal, expired items, quiet time and disabled private context are rechecked. The Mac uses its enrolled Web Push subscription. The iPhone Simulator uses the installed native app’s permission, current server binding and a single operator-pinned Simulator. A lock-screen notification contains generic text. The Simulator transport uses Apple’s supported push simulation. [Apple Simulator release notes](https://developer.apple.com/documentation/Xcode-Release-Notes/xcode-14-release-notes) · [Apple’s native notification contract](https://developer.apple.com/documentation/usernotifications/registering-your-app-with-apns).

The operator renewed the existing local FYP ledger for six months. Each request must fit both the Hong Kong calendar day and month in the same SQLite reservation transaction. The first month includes the official organization cost opening. The conservative day boundary, observed usage estimates and historical unpriced reservations are identified separately. The previous release’s allowance remains expired, which prevents rollback to old code from silently reopening daily-only spending. The Simulator uses its server’s allocation. There is one paid host for these checks. Account figures, the cost CSV and operator limits remain in private storage. Hosted automation was considered against the existing worker and account boundary. [Official scheduled automations](https://developers.openai.com/api/docs/guides/agents-api/sessions/automations).
