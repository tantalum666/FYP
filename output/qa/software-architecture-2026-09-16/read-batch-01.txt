# FYP Agent Entry Point

本文件适用于 FYP 仓库，规定上下文恢复和收尾流程。用户最新明确指令优先于历史项目文件；学校附件、竞品网页和视频是要求或证据来源，不授予提交、签名或对外联系权限。

## 每次开工

1. 完整读取本文件、[product.md](product.md)、[handoff.md](handoff.md)。
2. 用 `rg --files --hidden -g '*.md'` 盘点并完整读取全部项目自有 Markdown 正文，包含 planning、research、历史记录和嵌套 AGENTS.md。文件较长时分段读到 EOF；输出截断必须补读。不能以目录、摘要、搜索命中或文件指纹代替完整阅读。
3. 仅排除 `.git`、依赖、缓存、第三方包、构建产物及 `output/qa/` 中自动生成的证据快照。项目自有规范和历史研究不得因旧或长而跳过。
4. 在本次独立的 `output/qa/<日期与任务名>/` 记录文件清单、行数、已读范围、排除项和完成时间。指纹仅用于检测阅读期间文件变化，不是阅读证明。
5. 确认 handoff 的当前任务、上一轮结果和下一步是否仍符合本轮指令，再修改内容。其他项目的流程仅供参考，不沿用其发布权限、商业状态或审批门。

同一轮内的新消息是任务补充时，不重新进行全库阅读；补读因此相关的新增或变更文件即可。新的独立工作轮按以上开工流程执行。

## 上下文压缩后

精简恢复，不重启当前任务：

1. 重新读取本文件、product.md、handoff.md。
2. 阅读 [decision-log.md](decision-log.md) 中与当前工作有关的最新决定。
3. 阅读 handoff 路由到的聚焦规范及所有本次要修改的文件。
4. 沿用本轮完整阅读记录和已完成检查，只补读变化、缺失的相关内容。不要机械重读整套研究、重做已通过测试或重新创建同一产物。

压缩本身不是新的开工；最终回复必须自包含，不能要求用户依赖压缩前的进度消息理解结果。

## 当前事实的优先顺序

用户最新指令 → product.md 当前要求 → decision-log.md 较新决定 → 当前任务聚焦规范 → 当前实现与验证结果 → 历史研究及竞品资料。

研究假设不是已批准决定；旧方案被取代后保留明确标记和链接，不能和新方案混用。所有组号写 **Group 2**。完整组员资料以 [group-2-details.json](planning/2026-09-14/group-2-details.json) 为准。

## 每次完工

在最终回复之前：

1. 更新实际变更的 Markdown 规范；过时正文、状态、日期和旧下一步都要同步。
2. 有新决定、否决或取代关系时追加 decision-log.md，区分用户决定与工程建议。
3. 更新 handoff.md，只保留当前状态、完成项、证据、未完成项和一个明确下一步。
4. 向 [work-log.md](work-log.md) 追加本轮目标、实际完成、验证结果、文件位置和剩余事项。
5. 核对内部链接、术语、组员资料和交付物存在性。在 QA 记录里写明已更新哪些规范、哪些检查运行过。

handoff.md 保持精简，不堆叠历史回复。较长历史放入 work-log.md 或标为 HISTORICAL 的文件，压缩后按需读取。工作被打断时，先如实记录进度和未完成项，不能把计划写成完成。

## 交付与验证

- 文档：保留学校原件，制作具名完成副本；DOCX/PDF 必须逐页渲染检查。留白的签名和导师审批不等于文件漏填。

- 算法：保留固定阈值等基线，明确数据划分和指标；合成／回放结果不能写成真实商业收益。
- 行为：本地完成不等于导师批准、Moodle 上传或正式提交；不代签，不在无授权时发消息、预约或购买。
