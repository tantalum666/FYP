## eBay order cancellation

After the program approves the account, its test-user tool provides separate buyer and seller identities. Use a dedicated low-price listing in the US sandbox and preserve the buyer's paid order number before requesting cancellation. The seller can approve or decline. eBay documents a full refund for an already paid order when the applicable cancellation succeeds. In the test, retain the seller decision and independently reopen the buyer's order and refund amount. [Sandbox users](https://developer.ebay.com/api-docs/static/sandbox-test-users.html) · [Cancellation guide](https://developer.ebay.com/api-docs/user-guides/static/post-order-user-guide/post-order-cancellations.html).

The first acceptance will use the normal sandbox buyer and seller interfaces. The actual controls and receipts will determine coverage. ## Independent refund verification

The existing [read-only Stripe verifier](../../../desk-companion/scripts/verify_stripe_sandbox_checkout.py) accepts an optional `--full-refund-file` with a private JSON `id`. It reopens the original Checkout, PaymentIntent, Charge and the specified Refund in the named test account. It checks both payment references, amount, currency, terminal refund status and the Charge's cumulative refunded amount. Its original paid-only check continues to require zero refunded amount. This supports one full refund in one operation. Ordinary Alice chat still has the existing WooCommerce checkout authority. [Stripe Refund retrieval](https://docs.stripe.com/api/refunds/retrieve).

The new protocol checks exercise successful readback, paid-only compatibility, incomplete and partial refunds, wrong currency, unrelated payment references, live-mode mismatch and disagreement between the Charge and Refund. The normal CLI also read the new provider records with the expected merchant reference, amount and currency. The operator saw exactly one linked refund. The only real external payment-service writes in the Visa control were in the dedicated Stripe sandbox. It produced no shipment or bank charge.

## Zinc ordering boundary

Stripe Directory surfaced Zinc. Used Zinc's official free test key with a fictional US address and the documented successful-order fixture. Two distinct sandbox orders used US$25.00 as the maximum permitted price. The first cancellation returned HTTP 204 while pending, followed by a GET reporting `cancelled` and zero retailer references. For the second order, a GET showed `order_placed` and one simulated retailer reference. Cancellation returned HTTP 400 with `order_not_cancellable`. A fresh GET retained `order_placed`. The test wallet balance was zero before and after. Neither order supplied a payment record. These cases establish the exact stage at which this provider can cancel through its API.
