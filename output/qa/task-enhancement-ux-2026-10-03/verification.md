## 已修复的交互发现

| 严重度 | 触发与影响 | 修改与验证 |
|---|---|---|
| P1 | 新事务日期控件画面有输入，但保存后截止／检查为空 | datetime-local改为onInput。实际新建中文事务读回10月5日18:00；英文编辑读回10月9日17:00及计划检查，并在04:03触发一次提醒 |
| P1 | 关闭面板或切换页面会丢失进展／表单／偏好输入 | 通用DraftGuard、父子面板与EventEditor退出保护、忙碌锁定、焦点恢复。管理页切换、设备父面板关闭和嵌套日历取消后继续编辑，输入均保留 |
| P1 | 跨端修改时简单报错，无法清楚恢复当前版本 | TaskEditor保留原稿，显示当前状态／下一步；用户明确加载当前版本后再编辑。通过另一客户端写入进展制造冲突，界面拒绝旧版本且恢复后成功保存 |
| P2 | 步骤看起来可勾选但仅为装饰；超过20行会静默截断 | 改为有44px触摸区域的真实复选框，逐项保存；超限保留21行并显示原因、禁止保存。整体完成仍单独确认 |
| P2 | 助理草稿显示原始操作码，部分设置不清楚；发送中仍能改输入 | 展示操作、状态、截止、跟进／隐私及步骤；停用正在处理的输入；已非等待状态不再展示旧等待原因。实际讨论进展→草稿→确认→历史读回 |
| P2 | 读取失败复用“保存可能成功”文案，重连后可能留下旧错误 | 区分只读断连与未知写入结果；断开QA服务观察禁用按钮，重启后自动恢复且错误消失，不重置数据库 |
| P2 | 事务列表与常亮入口已有新提示，详情历史只按任务版本更新 | 历史缓存键加入跟进ID，恢复可见时即时读取；Today加事务摘要。后台本身按时正常生成，早期怀疑“调度未工作”不成立 |
| P2 | 320px手机列表贴边，导航与筛选可能挤压；日期显示中英格式混用 | 增加手机内边距、五项底部导航均分、表单单列、中文日期格式。实际320×740无横向溢出；1024×600设备继续独立月历／大时钟 |
| P2 | 新事务面板未使用常亮隐私投影，缓存详情可能在失联后保留 | 设备请求display投影，服务端详情拒绝隐藏私人记录；前端遮蔽失联／离桌私人缓存，未保存内容保留在页面内存。已保存私人任务在设备中隐藏，在已授权手机仍可管理 |
| P2 | 1280×720常亮区间规则把第三项重新显示，出现半截事项 | 移除冲突的短容器覆盖规则，保留两项完整安排。实测第二项底部506px，页脚603px，第三项隐藏；触摸月历仍可访问全部 |
| P2 | 活动记录把本人／规则的来源都写成Live input | 区分本人录入、本人确认、已确认助理草稿、计划检查、备份与传感器来源；Records筛选实际读回 |
| P2 | 周期事项的操作范围容易被理解为影响“完成” | 明确“Edit or delete scope”与“Complete this occurrence”；没有改变原来仅完成发生项的业务语义，相关既有自动化回归仍通过 |

审查覆盖可发现性、反馈与状态、输入保留、关闭／恢复、异步与版本冲突、错误文案、触摸尺寸、隐私及英简。上述发现均已修复；本轮范围内没有已知阻断主流程的未修复交互项，不代表整个平台不存在其他缺陷。
