| A local transport replay removed the revision from a second genuine merchant conflict. | Alice reported unmatched payment records and an amount awaiting verification. | In the same conversation, the owner requested alternatives for the unavailable stationery pack, under HK$33 delivered, and explicitly selected `FYP-QA-BASKET-ALT`. | Before selection, the proposal had no payable amount. Selecting the SKU produced a fresh unapproved HK$33 review for the replacement and both tissue packs, including one HK$8 delivery fee. The original approval still led only to its stopped review. Attempting payment with the stale choice version returned 409. The owner declined the fresh review and the merchant had no mapped replacement order. |

The normal app message endpoint used scripted Sessions tool arguments, the Woo store API and the authenticated merchant guard on the disposable clone. Static rendering of the actual persisted candidate rows confirmed the home copy, absence of a payment control on the stopped item, and separate alternative-selection controls. A clone-only fallback that would prevent gateway dispatch even on a regression was never reached. Account-level before/after reads found zero new Stripe intents or charges. The test shop’s normal product stock state was restored, the normal merchant’s control snapshot matched, and the isolated clone was stopped.
